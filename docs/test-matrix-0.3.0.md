# 0.3.0 表示変更URL一覧・PC／Android重点テスト

作成日：2026-11-04。対象は現在の0.3.0開発版、ソース基準コミット `c9cebb0`と今回の作者指定判定の修正を含む作業ツリー。この一覧はソースのURL判定とDOM判定を整理したもので、実機の確認結果ではない。全結果を「未」で開始する。READMEは変更しない。作者検索の判定変更を含む最新0.3.0配布物で確認する。

## 最初に

- PCとAndroidの設定画面右上が0.3.0か確認し、同じ最新ビルドを使う。PCの狭幅表示はAndroid実機の確認に代用しない。PC側はブラウザ名も記録する。
- 自分のユーザー名を設定。以下のruminarは必要なら自分のIDへ置き換える。現在の設定JSONを控えてから確認すると元へ戻しやすい。
- 通常モードで表示し、対象機能のチェックON／OFFを切り替えて比較する。共通左メニューは通常／重度／社会復帰／拡張OFFを比較する。
- 各URLはリンクから直接開く場合と、note内のリンク・タブを辿る場合を確認する。後者はSPAの更新漏れを検出するため。
- ログインが必要な画面はログイン後に確認。ログイン画面へ飛ばされた場合、元の画面を確認済みにしない。紹介した記事の公開・価格状態や公式タブの現時点の存在は、この一覧作成時には再確認していない。
- 結果欄は「OK」「NG」「対象DOMなし」「未」に書き換える。単に枠が見つからない場合と、表示・復元の不具合を分ける。

| 処理 | URL条件 | 設定・例外・補足 |
| --- | --- | --- |
| 公式ホームの転送 | `/`（クエリ・ハッシュ可） | 通常・重度。社会復帰と拡張OFFでは転送しない。 |

| 作者検索リンク・アイコン・強調 | `/search`のqから引用外の独立した正の`from:@ID`が1人に確定 | context未指定・note・magazine。追加語を許容し、同一IDの重複は1人扱い。引用内・除外指定は拾わない。異なる複数作者、q／context重複、不正・予約ID、未閉じ引用は除外。登録済み作者に限らない。 |
| 作者プロフィールへの追加UI | `/{id}` と既知のプロフィール配下 | 作者管理は全モードで利用可能だが自分は除外。作者お気に入りは通常だけ。TL導線は通常・社会復帰。ストアも既知枠へ追加。 |

| 関連商品枠非表示 | タグ画面 | 通常・社会復帰で有効。重度とOFFでは解除。既知の商品枠だけ。 |

## note.com全体で動く共通処理

Manifestのcontent scriptは`https://note.com/*`を対象としている。したがって、上の個別URLだけが表示変更されるわけではない。以下はURLよりもDOM構造で対象を決める。

| 処理 | 適用条件 | 適用しない／維持するもの |
| --- | --- | --- |
| ヘッダ固定 | 拡張ON＋ヘッダ常時表示ON＋既知の公式ヘッダ | 未知のヘッダ・本文は変更しない。作者ページの公式固定バーと、共通左カラムの位置も調整。 |
| ロゴのブラウザバック | 通常・重度＋ロゴ戻りON | 社会復帰は公式ホームへ。戻れるnote内履歴がない場合はその場に留まる。修飾クリック等の通常操作を維持。 |
| 歯車リンク | 社会復帰、またはロゴ戻りON | 既知の公式ロゴ周辺だけ。拡張OFFで撤去。 |
| 検索欄のクリア | 拡張ON＋既知の公式検索フォーム | 入力中・IME変換、クリア後の入力フォーカスを確認。本文中など無関係なフォームは変更しない。 |
| スキ数非表示 | 拡張ON＋スキ数非表示ON＋既知の操作部品／埋め込み | 操作ハートは維持し数字だけ隠す。表示専用はハートごと。押下後の「スキを取り消す」も対応。全モード・自己・許可作者にも適用。 |
| 有料カード非表示 | 拡張ON＋有料非表示ON＋既知の記事／マガジンカード | `/notes/purchased`とその配下は除外。本文内のカードはこの有料判定では隠さない。表示許可した作者の既知カードは残す。自分だから全ての有料カードが免除される、という実装ではない。 |
| 作者によるカード非表示 | 拡張ON＋自己ID設定＋非表示ルール＋既知の記事カード | プロフィール扱いのURLと購入済み一覧は除外。記事本文や直接アクセスは制限しない。自己は対象外。 |
| 作者情報欄のフォローボタン | 拡張ON＋公開記事／プレビューの既知の固定作者欄（全モード） | 記事の作者名横のフォローリンクやアイコンホバーのカードを一括で消す機能ではない。 |

URLが対象でも既知DOMがなければ変更しない。これを「対象DOMなし」として、実際の不具合と区別する。

## 不具合を報告するとき

一覧No.、実際のURL、端末／ブラウザ、モード、関係する設定のON/OFF、「期待した表示」と「実際の表示」を記録する。画像があると位置・幅の問題を確認しやすい。ログインが必要なURLやプレビューの鍵などは伏せてよい。

## 確認元

- `src/common.js`：URL分類、検索URL、作者指定の識別、転送条件。
- `src/content.js`：ページ全体への適用、歯車の遷移先、ダッシュボードリンク、ロゴ／タブ操作。
- `src/note-ui.js`と`src/content.css`：各ページの専用処理・共通DOM処理・幅条件・復元。
- `src/routing.js`：ホーム／ダッシュボードのルール。
- `src/home.js`と`home.html`：設定画面・表示管理・お気に入り・移行。
- `manifest.json`と`manifests/firefox.json`：適用オリジン、配布対象、版番号。

この資料は判定条件の棚卸し。全行を実機で通過したことや、未知のnote画面を全て確認したことを示さない。
