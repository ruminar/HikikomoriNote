## 0.1.1：ダッシュボードの任意無効化（2026-10-22）

自動テスト36件・構文検証済み。2026-10-22に利用者より、ボタン非表示・配下URLの転送・解除後の復帰を実ブラウザで確認済みとの報告あり。ブラウザ名および以下の詳細項目ごとの結果は未記録です。提出済み0.1.0とは別の0.1.1更新候補として確認してください。拡張機能を再読み込みした後、noteの既存タブと専用ホームも再読み込みします。

1. 旧設定・新規導入では「ダッシュボードを無効化する」が未選択で、ダッシュボードとメニューのボタンが利用できる。
2. チェックを入れて「ユーザー設定を保存」。noteのアカウントメニューを開くとダッシュボードだけが消え、隣の設定は利用できる。メニューを閉じて開き直しても同じ。
3. アドレスバーから `/dashboard`、`/dashboard/suggestions`、その他のダッシュボードサブメニューURLへ移動すると専用ホームになる。query/hash付き・別タブ・履歴移動も確認する。
4. 既にダッシュボードを開いている別タブも、無効化設定を受信すると専用ホームへ移動する。記事・プロフィール・アカウント設定は利用できる。
5. チェックを外して保存すると、開いたままのnoteタブでもボタンが復帰し、ダッシュボードに移動できる。
6. 再度チェックして保存し、拡張再読み込み・ブラウザ再起動後も設定が保持されることを確認する（Firefoxの一時アドオンは終了時に外れる）。
7. チェックしたまま全体OFFにすると、ダッシュボードとボタンが復帰する。拡張アイコンでONに戻すと再度制限される。
8. Networkで対象URLの文書が内部転送され、対象URLの事前取得が遮断されることを確認する。別URLのAPI通信はこの機能の対象外。

## 通信の確認

1. 専用ホームでON・ルール適用済みを確認してから、プロフィールを開きます。
2. 開発者ツールのNetworkを開き、Preserve log（ログ保持）とDisable cacheをON、記録を消去します。
3. 左上のnoteロゴを押します。専用ホームへ直接移動し、通常ホームの文書の取得がないことを確認します。
4. アドレスバーから `https://note.com/` を入力し、通信前の内部転送で専用ホームになることを確認します。Networkに元URLの行が出ても、内部転送・ブロックの記録とサーバーから取得した応答を区別してください。応答ヘッダー・転送理由・接続先・Timingを確認します。
5. query付き、別タブ、再起動後についても同様に確認します。
6. OFFに切り替えると通常ホームの文書取得が再開することを確認します。

遮断の対象は `https://note.com/` そのものです。note側が別URLのAPIやService Workerで取得する情報、ルール適用前に発行済みの通信まで遮断するものではありません。ホームへの表示遷移を伴わない先読みも含め、実サイトでの通信状況はこの手順で確認が必要です。
