# ひきこもりnote v0.2.0 設計書

- **プロジェクト名**：ひきこもりnote
- **リポジトリ名（既存案）**：`hikikomori-note`
- **対象バージョン**：`0.2.0`
- **作成日**：2026-10-24
- **設計レビュー反映日**：2026-10-24（編集競合、OFF時の復帰、自動保存、正規化、表示フォールバック、参照名を確定）
- **文書種別**：v0.1.1からの機能追加・画面設計・受け入れ条件
- **対象環境**：Google Chrome / Microsoft Edge / Mozilla Firefox（既存の試用対応を維持）
- **前提**：既存のv0.1.1実装とその仕様・検証済み挙動を壊さずに拡張する。

> **枠を超えたら落選したので、殻を作りました。**
>
> 本リリースでは、note標準の「フォロー中」「ハッシュタグ」「クリエイターページ」を、ユーザーが選択したタグでつなぐ。記事の取得・再描画は原則としてnoteに任せる。

## 1. 今回の結論と適用範囲

### 1.1 目的

v0.2.0の目的は**自分専用のナビゲーションを作ること**である。専用ホームでお気に入りハッシュタグを管理し、note標準のフォロー中画面とタグ画面の左メニューを共通ナビゲーションに置き換える。また、任意のクリエイターページからフォロー中画面へ戻る入口を追加する。

ページ内の記事一覧・スキ・コメント・フォロー操作など、note標準機能は可能な限り変更しない。

### 1.2 今回実装する機能

| ID | 機能 | v0.2.0で行うこと |
|---|---|---|
| F-201 | 専用ホームの3タブ化 | 「メイン」「お気に入りタグ」「設定」 |
| F-202 | メイン画面 | 自分のページ、フォロー中、お気に入りタグへのリンク |
| F-203 | タグ管理 | 件数の固定上限なし、追加・削除・並べ替え・保存 |
| F-204 | フォロー中画面の左メニュー | 「フォロー中」＋お気に入りタグに置換 |
| F-205 | タグ画面の左メニュー | F-204と同じ共通メニューに置換 |
| F-206 | クリエイターページの帰還導線 | 左カラムのプロフィールより**上**に「フォロー中画面へ」 |
| F-207 | 既存機能との互換 | v0.1.1の転送、ON/OFF、ダッシュボード無効化等を維持 |

### 1.3 今回実装しない機能

- フォロー中ユーザーを独自に列挙・管理する**ユーザーリスト**。
- メンバーシップの独自一覧・管理機能である**メンバーシップリスト**。
- ハッシュタグ記事の自動収集、独自フィード統合、「もっと見る」の自動クリック、1時間単位のフィードキャッシュ。
- 自分や他人のプロフィールページ全体のキャッシュ化・高速化。
- AI要約、ChatGPT連携、スキ・フォロー・コメントの自動操作。
- noteの共通上部ヘッダーの書き換え、公式の記事表示の置き換え。
- サイドバー内の「設定」リンク。noteロゴから専用ホームへ戻れる既存導線を使う。

**ユーザーリストとメンバーシップリストはv0.2.1以降の検討候補とし、今回の実装指示には含めない。** 大きな追加機能になる場合は、v0.3.0など次のマイナーバージョンとして扱ってよい。実装時期・詳細仕様は未決定。

> 注意：「フォロー中画面への**リンク**」はv0.2.0の対象。「フォローしているユーザーの**独自リスト**」は対象外。両者を混同しないこと。

### 2.1 画面遷移

```text
                         noteロゴ（既存導線）

                 ひきこもりnote 専用ホーム
                  ┌────────┬────────────┬───────┐
                  │ メイン │お気に入りタグ│ 設定  │
                  └────────┴────────────┴───────┘
                         │         │
                  公式画面への移動  タグ設定の保存
                         │

       フォロー中画面             ハッシュタグ画面

                            │
                   任意の作者のプロフィール
                            │
             左上「フォロー中画面へ」ボタン

```

### 2.2 URL適用範囲

| URL・画面 | 処理 |
|---|---|
| `https://note.com/` | v0.1.1どおり専用ホームへ転送（変更なし） |
| `https://note.com/following` | 共通左サイドバーを適用 |
| `https://note.com/hashtag/<タグ名>` | 共通左サイドバーを適用 |
| `https://note.com/tag/<タグ名>` | 共通左サイドバーを適用（リダイレクト後も対応） |
| `https://note.com/<ユーザー名>` | クリエイターページ左カラム先頭に帰還ボタン |
| クリエイターページの各タブ・下層ページ | **同じプロフィール左カラムが実在する場合**に限り帰還ボタンを適用。DOM確認が必要 |
| 記事本文 `/ユーザー名/n/<記事ID>` | 変更しない |
| `/dashboard` とその配下 | v0.1.1の制限を維持 |
| `/api/`、ログイン、設定、投稿・編集、購入等 | 今回の機能は介入しない |

URL文字列だけでクリエイターページと決めつけない。予約済みパスや記事URLを除外し、**プロフィールとして確認できるDOM**と合わせて判定する。タグ名は必ずURLエンコードする。クエリ文字列やフラグメントは、画面判定に必要な範囲で扱う。

公式のタグ遷移先は実ブラウザで正規URLを確認して決める。左サイドバーを確認できる画面では、`/hashtag/` と `/tag/` の双方で機能させることを必須とする。未ログイン画面・狭い表示などで対象領域がない場合は、第4.2節のフォールバックを優先する。

## 3. 専用ホームの画面仕様

### 3.1 基本レイアウト

- 上部にアプリ名と既存の状態表示を維持。
- **3タブ**：「メイン」／「お気に入りタグ」／「設定」。
- 専用ホームを新規表示したときの初期タブは**メイン**。
- タブ切り替えは同一ページ内で行い、基本的に再読み込みしない。
- 既存の保存済み設定は維持する。初回アップグレードでユーザー名やダッシュボード設定を失わせない。

### 3.2 メインタブ

**日常の閲覧・移動専用。タグ編集操作を置かない。**

```text
┌─────────────────────────────────────┐
│ ひきこもりnote                       │
│ [ メイン ] [ お気に入りタグ ] [ 設定 ] │
│                                     │
│ クイックアクセス                    │
│ [ 自分のページ ] [ フォロー中 ]        │
│                                     │
│ お気に入りハッシュタグ              │
│   # ComfyUI                         │
│   # HandpickerSuite                 │
│   # 創作大賞2026                    │
│   ...                               │
└─────────────────────────────────────┘
```

- 「自分のページ」：設定済み `noteUserId` の公式プロフィールへ移動。ユーザー名が未設定なら、設定を促す（架空のURLを生成しない）。
- 「フォロー中」：`https://note.com/following` へ移動。
- タグリンク：保存された順番で表示。クリックでnoteの公式タグ画面へ移動。
- 登録タグ0件なら空状態を案内する。
- タグ追加・削除・並べ替えの操作子はメインには配置しない。

### 3.3 お気に入りタグタブ

**タグの編集専用。**

- タグ名を入力して追加。正規化・重複判定は第6.4節に従う。
- 登録件数に**固定の上限を設けない**。ただし保存容量・表示性能などプラットフォームの実際の制約には従う。
- 空白だけの入力、空タグ、正規化後の保存値が完全一致する重複は拒否する。大文字小文字・全角半角・内部の空白を勝手に同一視しない。
- 登録済みのタグは自由に削除できる。
- ドラッグ＆ドロップで並べ替えできる。キーボードやタッチ環境のために**上下移動ボタン**も用意する。
- 保存された配列の順番が、メインタブと共通サイドバーの表示順になる。
- 追加・削除・並べ替えの**操作ごとに自動保存**する。タグ一覧用の一括保存ボタンは設けない。ユーザー名・ダッシュボード設定は従来の保存ボタンを維持する。
- 変更は背景処理で `storage.local` に永続化する。保存成功後にUI状態を確定し、失敗時は最後に確認できた保存済み一覧を保持・復元してエラーを表示する。ドラッグ中の仮表示は保存済み状態と区別する。
- 入力途中の文字列は画面ローカルの状態とし、別タブの更新・タブ切り替え・保存失敗で消さない。追加入力を消すのは、その追加の保存成功が確認できた場合だけとする。既存設定の未保存の入力も、タグ一覧の更新だけでは上書きしない。
- 同じ画面で操作結果が未確定の間は、次のタグ変更操作を受け付けない。入力文字列の編集は可能とする。並べ替え失敗時は保存済みの順番へ戻し、エラーを表示して再操作できるようにする。
- 同じ専用ホーム内のメインタブへの反映は**即時**を基本とする。別タブの共通サイドバーへはストレージ変更イベントで追随する。再読み込みなしの即時反映に重大な実装上の障害があれば、明示的な再読み込みを代替案とし、その旨を報告する。

### 3.4 設定タブ

項目の順番を固定する。

1. **noteユーザー名**（既存機能）
2. **ダッシュボードを無効化**（既存機能）
3. 区切り線
4. **通常のnoteを表示（OFF）**（既存機能）

既存のユーザー名・ダッシュボード設定の保存方法とエラー処理を引き継ぐ。OFF操作は単なるURL移動ではなく、既存の背景処理で転送ルール解除・状態保存を完了させてから通常noteへ移動する。

「通常のnoteを表示（OFF）」は**設定タブの下部のみ**に配置する。全タブ共通の固定フッターには置かない。

## 4. フォロー中・ハッシュタグ画面の共通サイドバー

### 4.1 表示内容

左メニューに表示するのは**「フォロー中」と登録済みタグだけ**。タグ順序は保存順。

```text
┌──────────────────────┐
│ フォロー中            │
├──────────────────────┤
│ お気に入りタグ        │
│ # ComfyUI             │
│ # HandpickerSuite     │
│ # 創作大賞2026        │
│ # 縄文部              │
│ ...                  │
└──────────────────────┘
```

- フォロー中項目は、どちらの画面でも常に最上段に置く。
- 現在のURLに一致する項目を選択状態として視覚的に示す。
- 登録タグがない場合でも「フォロー中」は使える。
- 件数が増えた場合も閲覧・スクロールでき、右側の記事表示を狭めたり隠したりしない。
- サイドバーに「設定」リンク、ユーザーリスト、メンバーシップリストは追加しない。
- タグやフォロー中の**右側にある公式コンテンツは維持**。スキ・並び順・記事閲覧・フォロー等を改造しない。

### 4.2 差し替え方式

- 変更するのは**対象画面の左サイドバー領域だけ**。note共通ヘッダー、ページ本体、右側の記事一覧には触れない。
- 元の左メニューは原則として削除せず、拡張ON中のみ非表示にする。
- 拡張側のメニューは独立した要素として管理し、React等が管理する既存要素の内部を無理に書き換えない。
- 実ブラウザでDOM構造を確認した上で挿入先と非表示対象を決める。未確認のCSSセレクターを推測して本番実装しない。
- 対象DOMが存在しない・構造変更された場合は**無理に差し替えない**。公式画面を維持し、必要なら診断可能な状態を残す。
- 未ログイン画面・幅の狭い画面などで左カラムが存在しない場合も、公式表示を維持して追加サイドバーを省略する。独自の代替メニューを別の位置へ挿入しない。表示幅の変更・再描画で対象領域が現れた場合は、確認済みの条件に従って再適用する。
- SPA遷移、戻る・進む、動的DOM再生成、別タブの設定変更、拡張OFF/ONに対応する。
- 重複挿入、無限MutationObserverループ、切り替え時の表示残りを防止する。
- CSSは拡張専用の識別子でスコープを限定し、他のnote要素への副作用を避ける。

## 5. 任意のクリエイターページへの帰還ボタン

### 5.1 目的と位置

自分のページだけでなく、**他ユーザーのプロフィールからもフォロー中画面に直接戻れるようにする**。

位置は、**カバー画像の下にある左カラムの先頭、ユーザーのアイコン・名前・紹介文よりも上**。マガジンなどの長いリストが後続してもボタンが下に流されない。

```text
┌──────────── 左カラム ────────────┐
│ [ フォロー中画面へ ]               │ ← 先頭
│                                  │
│ 〔アイコン〕 ユーザー名            │
│ 自己紹介・フォロー操作等（純正）   │
│                                  │
│ マガジン一覧等（純正）             │
└──────────────────────────────────┘
```

### 5.2 動作

- ボタンのリンク先は常に `https://note.com/following`。
- ブラウザの履歴に依存する「戻る」動作ではない。
- ボタン以外のプロフィールの機能、フォロー操作、各タブ、マガジン表示は変更しない。
- 対象は**全ユーザーのクリエイターページ**。プロフィール左カラムが確認できるページに限って追加する。
- プロフィール情報の上であって、note全ページ共通の上部ヘッダーには挿入しない。
- 遷移やDOM再生成時にボタンを二重挿入せず、OFFで除去する。
- 未ログイン画面・狭い画面などでプロフィール左カラムを確認できない場合は、公式表示を維持して帰還ボタンを省略する。別の位置に代替ボタンを追加しない。

## 6. 設定・データモデル

### 6.1 既存設定と新規項目

v0.1.1の保存形式を維持したまま、**`favoriteTags`** を追加する。

```ts
// 設計上の概念型。既存コードをTypeScriptへ移行する指示ではない。
type Settings = {
  enabled: boolean;            // 既存
  noteUserId: string;           // 既存
  dashboardDisabled: boolean;   // v0.1.1既存、未設定時false
  favoriteTags: string[];      // v0.2.0新規、未設定時[]
};
```

- ストレージは既存の `storage.local`。
- v0.1.1からアップグレードしたとき、`favoriteTags` が未定義なら空配列と解釈する。
- 保存済みの `enabled`、`noteUserId`、`dashboardDisabled` を消さない。設定の部分更新方式・単一書き込み管理を維持する。
- フォロー中・タグ画面のサイドバーとメインタブは**同じ `favoriteTags`** を参照し、別々のコピーを恒久保存しない。
- 他ブラウザへの同期、新たな外部サーバー、認証情報の収集は追加しない。

### 6.2 アクセス時の動作

- 専用ホームは既存の保存データを読み込み、メインを最初に表示する。
- タグ管理の変更保存が成功したら、ホーム内の表示へ反映する。
- 開いている別タブに対しては、`storage.onChanged` または既存APIアダプター相当の仕組みで更新する。
- OFFの場合、左メニュー置換や帰還ボタンなどの追加UIを適用しない。

### 6.3 タグ操作の直列化と競合

- タグ配列全体を画面側から保存する方式は使用しない。画面は次の操作を、既存APIアダプターを通して背景処理へ送る。メッセージ名は実装時に既存規約と整合させてよい。

```js
{ type: "ADD_TAG", tag: "ComfyUI" }
{ type: "REMOVE_TAG", tag: "ComfyUI" }
{ type: "MOVE_TAG", tag: "ComfyUI", beforeTag: "AI" }
{ type: "MOVE_TAG", tag: "ComfyUI", beforeTag: null } // 末尾へ移動
```

- タグ操作と既存設定の保存は、同じ背景処理の単一キューで直列化する。各操作の実行時に保存済みの最新状態を読み、対象の変更だけを適用する。保存完了または失敗を確認してから次の操作へ進む。
- ADDは最新一覧の末尾へ追加する。同一保存値が既にあれば重複エラーとする。A・Bが異なるタグを同時追加しても両方残す。順序は背景処理で実行した順とする。
- REMOVEはタグの保存値を指定する。MOVEは移動するタグと移動先のタグの保存値を指定する。古い配列のインデックスは送らない。
- MOVEは最新配列から対象を取り出して `beforeTag` の直前へ移す。`null` は末尾を示す。自分自身への移動は変更なしとする。
- 削除・移動対象または移動先が既に削除されていた場合は、競合として通知し、その操作による保存は行わない。最新一覧を確認して再操作できるようにする。別タブが保存した変更を古い画面の配列で巻き戻さない。
- 同一タグへの複数の移動は、それぞれ実行時の最新配列へ受信順に適用する。古い画面で意図した一覧全体の並び順を固定・復元する機能は設けない。
- 保存完了後の結果応答と既存のストレージ変更イベントを使って画面を更新する。操作要求の送信元は、既存設定保存と同じく自拡張の専用ホームに限定する。

### 6.4 最小限の正規化と不正な保存データ

- タグ入力の前後の空白を取り除き、先頭の半角 `#` を除去する。除去後にも前後の空白を取り除き、空文字になった場合は拒否する。
- 大文字小文字・全角半角・内部の空白は変換しない。Unicode正規化による自動統合も行わない。重複は正規化後の文字列の完全一致だけで判定する。

| 入力 | 保存値 |
|---|---|
| `  #ComfyUI  ` | `ComfyUI` |
| `#創作大賞2026` | `創作大賞2026` |
| `ComfyUI` | `ComfyUI` |
| `comfyui` | `comfyui`（上のタグと別項目） |
| `ＡＩ` | `ＡＩ` |
| `AI` | `AI`（上のタグと別項目） |

- URL生成時は保存値をタグ名の1セグメントとしてエンコードする。保存値にエンコード済みURLや表示用の `# ` を格納しない。
- 保存済み配列に不正な型・空項目・重複等が混在している場合は、利用できる正常項目を順番どおり残し、異常を報告する。読み込みだけでストレージを空配列へ上書きしたり、破損項目を無言で消したりしない。
- `favoriteTags` 自体が配列でない場合も「未設定」と区別して異常を報告し、元の保存値を自動で置き換えない。正常な既存設定は引き続き利用できるようにする。
- 異常データのあるタグ一覧への書き込みは停止し、明示的な修復方法を案内する。破損項目の自動修復や独自のバックアップ基盤は今回の機能範囲に含めない。タグ以外の設定保存でも、不正なタグデータを空配列に変えて消さない。

### 6.5 背景処理の停止・再起動と保存結果

- 同一の背景実行環境内ではPromise等の単一キューを使う。ChromiumのService WorkerやFirefoxの背景処理のメモリー上の配列を、保存データの正本としない。
- 背景処理の再起動後は `storage.local` の最新状態を読み込み、新たに受け付けた操作を適用する。永続操作キュー・独自DB・独自トランザクション基盤は追加しない。
- 操作を受信しただけで成功を返さない。`storage.local` の保存完了を確認してから成功応答を返す。通常の保存失敗時は成功表示を出さず、以前の確認済み状態を維持する。
- 保存が完了していても、停止や接続切断で成功応答だけ失われる可能性がある。その場合は成功・未保存のどちらとも即断せず、結果未確認として表示し、背景処理への再接続後に保存済みの最新状態を取得する。操作を無条件に自動再送しない。
- 最新状態を再取得するまでタグ変更操作を停止し、入力途中の文字列を保持する。復旧後は確認できた一覧を表示して利用者が再操作できるようにする。背景処理に届かなかった要求の自動復元や、必ず1回だけ実行される保証は設けない。
- 既存ON/OFF等の転送ルール更新・保存失敗時のロールバックは維持する。タグ操作の失敗・再起動後も、既存設定を初期化しない。

## 7. 既存のv0.1.1から守るべきもの

1. `https://note.com/` の文書アクセスを拡張専用ホームへ転送する既存動作。
2. 拡張アイコンによるON復帰、設定からのOFF、失敗時のロールバック。
3. `dashboardDisabled` による `/dashboard` および配下への転送・リンク非表示。
4. OFFでは開いているnote画面の公式メニューを再表示し、拡張が追加したサイドバー・帰還ボタンを除去する。設定からのOFF操作後の移動先は従来どおり `https://note.com/`。直前のURLへ戻す機能は追加しない。ON復帰は従来どおり拡張アイコンから専用ホームを開き、設定値は保持する。
5. Chrome/Edge/Firefox用の既存ビルド・Manifest生成、`src/platform/browser-api.js` のAPI差分吸収。
6. 日本語ロケール、配布パッケージ、既存の検証スクリプト。
7. 投稿・編集・決済・認証・記事本文など、v0.1.1で触っていない画面を壊さない。

現行の実装内容とこの文書が衝突する場合、**既存機能を破壊する変更を勝手に実施せず、差分を報告**する。

## 8. 非機能要件

### 8.1 軽量・保守性

- 本リリースのためにタグフィードの収集・定期更新・独自記事キャッシュを実装しない。
- 既存ページへの余計なネットワーク要求を増やさない。タグリストはローカル設定だけで描画する。
- DOM監視は対象領域に限定し、更新が必要なときだけ最小限の処理を行う。
- サイドバー差し替えの共通処理を再利用し、フォロー中画面とタグ画面に同じロジックを重複実装しない。

### 8.2 安全性・アクセシビリティ

- タグ名・ユーザー名は信頼できない文字列として扱い、HTML文字列として無検証に挿入しない（`textContent` 等を使用）。
- タグURLはエンコードし、`javascript:` 等の不正URLを生成しない。
- キーボードでタグの追加・削除・順序変更・リンク操作ができるようにする。
- スクリーンリーダー向けのボタン名と現在選択項目の状態を適切に設定する。
- ブラウザ拡張の追加権限を最小化し、要求する場合は理由を明記する。
- noteが変更したDOMに誤適用する危険がある場合は、強引な削除ではなく公式画面を残す。

## 9. 実装前の確認事項（Codexで調査）

画面設計は確定。以下は**技術検証項目**であって、新しい機能提案ではない。

1. `/following` の左メニューの実DOMと、その外側のレイアウト境界。
2. `/hashtag/<タグ>` および `/tag/<タグ>` の左メニューの実DOM、正規遷移URL。
3. クリエイターページの左カラム先頭への安全な挿入位置。自己ページ・他人ページ・マガジンの多いページを含む。
4. noteのSPA遷移・後挿入・再描画で、注入した要素がどう扱われるか。
5. Chrome/Edge/FirefoxでのContent Script・CSSの適用タイミングと解除方法。
6. 幅の狭い画面など、左カラムが存在しない表示での安全なフォールバック。

**DOMが未確認の間は仮のセレクターを本番用コードに埋め込まないこと。** 実環境で確認できない箇所は未検証として記録し、検証手順を文書化する。
