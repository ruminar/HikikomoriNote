## 1. 今回の結論と適用範囲

### 1.1 目的

v0.2.0の目的は**自分専用のナビゲーションを作ること**である。通常モードでは、専用ホームでお気に入りハッシュタグを管理し、note標準のフォロー中画面とタグ画面の左メニューを共通ナビゲーションに置き換える。また、任意のクリエイターページからフォロー中のTL戻る入口を追加する。

追加ナビゲーションを使わずに過ごしたい場合は、**「0.1.1モード（重度引きこもりモード）」**を選択できる。拡張全体をOFFにせず、v0.1.1相当のシンプルな機能を利用するための独立した設定である。以降「重度引きこもりモード」と略記する。

ページ内の記事一覧・スキ・コメント・フォロー操作など、note標準機能は可能な限り変更しない。

### 1.2 今回実装する機能

| ID | 機能 | v0.2.0で行うこと |
|---|---|---|
| F-201 | 専用ホームのタブ | 通常モードは3タブ、重度引きこもりモードは「設定」のみ |
| F-202 | メインとクイックアクセス | 通常モードのメインにお気に入りタグ。クイックアクセスは通常時はメインタブ内、重度時は設定タブ先頭に配置 |
| F-203 | タグ管理 | 通常モードで件数の固定上限なし、追加・削除・並べ替え・保存 |
| F-204 | フォロー中画面の左メニュー | 通常モードかつ拡張ON時に「フォロー中のTL」＋お気に入りタグへ置換 |
| F-205 | タグ画面の左メニュー | F-204と同じ有効条件・共通メニューへ置換 |
| F-206 | クリエイターページの帰還導線 | 通常モードかつ拡張ON時に、左カラムのプロフィールより**上**へ「フォロー中のTL」 |
| F-207 | 既存機能との互換 | v0.1.1の転送、ON/OFF、ダッシュボード無効化等を維持 |
| F-208 | 0.1.1モード（重度引きこもりモード） | 追加ナビゲーションを停止し、自分のページ・既存機能・保存済み設定を維持 |
| F-209 | タグ画面の関連商品枠を非表示 | 通常モードかつ拡張ON時、確認済みの商品カードと見出しを持つsectionだけを余白ごと隠す |
| F-210 | 記事のおすすめ欄を選択して非表示 | 設定保存後、記事下の「あなたへのおすすめ」枠を両モードで非表示。初期値は表示 |
| F-211 | 表示中のタグをお気に入りに追加 | 通常モードかつ拡張ON時、タグ画面の共通左メニューから現在のタグを末尾へ追加 |
| F-212 | 記事画面の固定帰還リンク | 通常モードかつ拡張ON時、広い画面の左余白へ「フォロー中のTL」を固定表示 |

### 1.3 今回実装しない機能

- フォロー中ユーザーを独自に列挙・管理する**ユーザーリスト**。
- メンバーシップの独自一覧・管理機能である**メンバーシップリスト**。
- ハッシュタグ記事の自動収集、独自フィード統合、「もっと見る」の自動クリック、1時間単位のフィードキャッシュ。
- 自分や他人のプロフィールページ全体のキャッシュ化・高速化。
- AI要約、ChatGPT連携、スキ・フォロー・コメントの自動操作。
- noteの共通上部ヘッダーの書き換え、公式の記事表示の置き換え。
- サイドバー内の「設定」リンク。noteロゴから専用ホームへ戻れる既存導線を使う。

**ユーザーリストとメンバーシップリストはv0.2.1以降の検討候補とし、今回の実装指示には含めない。** 大きな追加機能になる場合は、v0.3.0など次のマイナーバージョンとして扱ってよい。実装時期・詳細仕様は未決定。

> 注意：「フォロー中のTLの**リンク**」はv0.2.0の対象。「フォローしているユーザーの**独自リスト**」は対象外。両者を混同しないこと。

## 2. 画面遷移と対象URL

### 2.1 画面遷移

以下は通常モードの遷移図。クイックアクセスはメインタブ内に置く。

```text
                         noteロゴ（既存導線）
                                  │
                                  ▼
                 ひきこもりnote 専用ホーム
                 自分のページ ／ フォロー中
                  ┌────────┬────────────┬───────┐
                  │ メイン │お気に入りタグ│ 設定  │
                  └────────┴────────────┴───────┘
                         │         │
                  公式画面への移動  タグ設定の保存
                         │
              ┌──────────┴────────────┐
              ▼                       ▼
       フォロー中画面             ハッシュタグ画面
              └──────共通左サイドバー────┘
                            │
                         記事を開く
                            │
                   任意の作者のプロフィール
                            │
             左上「フォロー中のTL」ボタン
                            │
                            └──────→ フォロー中画面
```

重度引きこもりモードでは「自分のページ」のクイックアクセスと「設定」タブだけを表示し、図中のフォロー中・タグへの独自導線は表示しない。公式URLへ直接移動することは禁止しない。モード変更だけではnoteタブのURLを変えない。

### 2.2 URL適用範囲

| URL・画面 | 処理 |
|---|---|
| `https://note.com/` | v0.1.1どおり専用ホームへ転送（変更なし） |
| `https://note.com/following` | 共通左サイドバーを適用 |
| `https://note.com/search`（検索語・context・mode付きも対象） | 共通左サイドバーを適用。検索フォーム・結果・対象切り替えタブは維持 |
| `https://note.com/hashtag/<タグ名>` | 共通左サイドバーを適用 |
| `https://note.com/tag/<タグ名>` | 共通左サイドバーを適用（リダイレクト後も対応） |
| `https://note.com/<ユーザー名>` | クリエイターページ左カラム先頭に帰還ボタン |
| `https://note.com/<ユーザー名>/followings`、`/followers` | フォロー・フォロワー一覧のプロフィール情報の上に「フォロー中のTL」。ページ番号付きも対象 |
| クリエイターページの各タブ・下層ページ | **同じプロフィール左カラムが実在する場合**に限り帰還ボタンを適用。DOM確認が必要 |
| 記事 `/ユーザー名/n/<記事ID>` | 本文は変更しない。F-210の設定によるおすすめ枠非表示と、F-212の本文外の固定帰還リンク |
| `/dashboard` とその配下 | v0.1.1の制限を維持 |
| `/api/`、ログイン、設定、投稿・編集、購入等 | 今回の機能は介入しない |

表の共通左サイドバー・帰還ボタンは、**`enabled === true && legacyMode === false`** の場合だけ適用する。重度引きこもりモードまたは拡張OFFでは追加UIを除去し、公式表示を維持する。フォロー中・タグ・プロフィールの公式ページ自体をブロック・転送しない。通常ホームへの転送とダッシュボード制限の条件は第6.6節に従う。

URL文字列だけでクリエイターページと決めつけない。予約済みパスや記事URLを除外し、**プロフィールとして確認できるDOM**と合わせて判定する。タグ名は必ずURLエンコードする。クエリ文字列やフラグメントは、画面判定に必要な範囲で扱う。

公式のタグ遷移先は実ブラウザで正規URLを確認して決める。追加UIの有効条件を満たし、左サイドバーを確認できる画面では、`/hashtag/` と `/tag/` の双方で機能させることを必須とする。未ログイン画面・狭い表示などで対象領域がない場合は、第4.2節のフォールバックを優先する。

## 3. 専用ホームの画面仕様

### 3.1 基本レイアウト

- 上部にアプリ名と既存の状態表示を維持。
- 通常モードでは**メインタブの内容の先頭**にクイックアクセスを配置する。お気に入りタグ・設定タブには表示しない。重度引きこもりモードでは設定タブの内容の先頭へキャッチコピーとクイックアクセスを差し込む。登録ユーザーのページへの入口はいずれのモードでも維持する。
- 通常モードは**3タブ**：「メイン」／「お気に入りタグ」／「設定」。重度引きこもりモードは「設定」だけを表示する。非表示のタブとパネルは、キーボード操作・支援技術からも選択できない状態にする。
- 専用ホームを新規表示したときの初期タブは、通常モードでは**メイン**、重度引きこもりモードでは**設定**。保存済み設定の読み込みが完了する前に通常モードのタグ一覧等を仮表示しない。
- タブ切り替えは同一ページ内で行い、基本的に再読み込みしない。
- モードを有効にした際、メインまたはお気に入りタグが選択中なら設定へ切り替える。別の専用ホームの設定変更でも同じ。モード解除後は3タブを復帰させ、表示中の設定タブを維持する。次回の新規表示はメインを初期タブとする。
- キャッチコピー「**枠を超えたら落選したので、殻を作りました。**」は、重度引きこもりモードの設定タブ内でクイックアクセスより上に表示する。通常モードでは表示しない。本書冒頭の引用は文書上の説明であり、通常モードの常時表示を指示するものではない。
- 専用ホーム内の「クイックアクセス」「お気に入りハッシュタグ」「お気に入りタグ」「設定」のh2見出しは表示しない。タブの名称とARIAのラベルで各領域を識別する。
- 既存の保存済み設定は維持する。初回アップグレードでユーザー名やダッシュボード設定を失わせない。

#### クイックアクセス（モード別の表示位置）

- ページボタンは登録ユーザー名を使った「<noteUserId>のページ」（例：`ruminarのページ`）と表示し、設定済み `noteUserId` の公式プロフィールへ移動する。「登録ユーザー：ruminar」のような別表示は設けない。未設定ならユーザー名設定ボタンを表示し、架空のURLは生成しない。通常モードはメイン内、重度モードは設定タブ先頭に配置する。
- 「フォロー中のTL」は通常モードのメインタブ内だけに表示し、`https://note.com/following` へ移動する。重度引きこもりモードでは非表示にする。登録ユーザーのページボタンと横並びにし、狭い幅では折り返せるようにする。
- 重度引きこもりモードでは唯一表示する設定タブ内で利用でき、非表示になるメインタブには依存しない。モード切り替え時は配置を切り替え、同じリンクをメインと設定タブ内へ二重に表示しない。

### 3.2 メインタブ

**通常モードの日常の閲覧・移動専用。タグ編集操作を置かない。** 重度引きこもりモードでは、このタブとタグ一覧を表示しない。

```text
┌─────────────────────────────────────┐
│ ひきこもりnote                       │
│ [ メイン ] [ お気に入りタグ ] [ 設定 ] │
│ [ ruminarのページ ] [ フォロー中のTL ] │
│                                     │
│   # ComfyUI                         │
│   # HandpickerSuite                 │
│   # 創作大賞2026                    │
│   ...                               │
└─────────────────────────────────────┘
```

- 登録ユーザーのページと「フォロー中のTL」のボタンを、メインタブ内の先頭へ横並びで配置する。
- タグリンク：保存された順番で表示。メイン・左サイドバーともに `https://note.com/tag/<エンコードしたタグ名>?mode=new` を生成し、新着を初期表示にする。note公式画面で利用者が人気順へ切り替える操作は妨げない。
- 登録タグ0件なら空状態を案内する。
- タグ追加・削除・並べ替えの操作子はメインには配置しない。

### 3.3 お気に入りタグタブ

**通常モードのタグ編集専用。** 重度引きこもりモードではタブ・一覧・編集UIを非表示にする。入力中の文字列は同じホーム内のローカル状態として保持し、モード変更を理由に登録済みタグを保存・削除しない。

- タグ名を入力して追加。正規化・重複判定は第6.4節に従う。
- 登録件数に**固定の上限を設けない**。ただし保存容量・表示性能などプラットフォームの実際の制約には従う。
- 空白だけの入力、空タグ、正規化後の保存値が完全一致する重複は拒否する。大文字小文字・全角半角・内部の空白を勝手に同一視しない。
- 登録済みのタグは自由に削除できる。
- ドラッグ＆ドロップで並べ替えできる。キーボードやタッチ環境のために**上下移動ボタン**も用意する。
- 保存された配列の順番が、メインタブと共通サイドバーの表示順になる。
- 追加・削除・並べ替えの**操作ごとに自動保存**する。タグ一覧用の一括保存ボタンは設けない。ユーザー名・ダッシュボード設定は従来の保存ボタンを維持する。
- 変更は背景処理で `storage.local` に永続化する。保存成功後にUI状態を確定し、失敗時は最後に確認できた保存済み一覧を保持・復元してエラーを表示する。ドラッグ中の仮表示は保存済み状態と区別する。
- 入力途中の文字列は画面ローカルの状態とし、別タブの更新・タブ切り替え・保存失敗で消さない。追加入力を消すのは、その追加の保存成功が確認できた場合だけとする。既存設定の未保存の入力も、タグ一覧の更新だけでは上書きしない。
- 同じ画面で操作結果が未確定の間は、次のタグ変更操作を受け付けない。入力文字列の編集は可能とする。並べ替え失敗時は保存済みの順番へ戻し、エラーを表示して再操作できるようにする。
- 同じ専用ホーム内のメインタブへの反映は**即時**を基本とする。別タブの共通サイドバーへはストレージ変更イベントで追随する。再読み込みなしの即時反映に重大な実装上の障害があれば、明示的な再読み込みを代替案とし、その旨を報告する。

### 3.4 設定タブ

重度引きこもりモードの場合だけ、タブ内容の先頭にキャッチコピーと登録ユーザーのページボタンを順に表示する。クイックアクセスの見出しは表示しない。その下に通常モードと共通の設定項目を配置し、以下の順番を固定する。

1. **noteユーザー名**（既存機能）
2. **ダッシュボードを無効化**（既存機能）
3. **記事の「あなたへのおすすめ」を非表示にする**（新規チェック項目）
4. **0.1.1モード（重度引きこもりモード）**（新規チェック項目）
5. **通常のnoteを表示（拡張OFF）**（既存のOFF操作）

ユーザー名・ダッシュボード設定・おすすめ非表示設定・モード設定の保存ボタンはOFF操作より前に配置する。OFF操作との区切り線を設けてよいが、上記の項目順序は変えない。

「状態を再確認」は設定タブ内の「ユーザー設定を保存」の隣に、保存を実行しない通常ボタンとして配置する。通常は操作不要で、保存済み設定の再取得・転送ルールの再適用・結果未確認時の復旧に使う。初回の設定読み込みに失敗した場合も設定タブと再確認ボタンを表示し、再試行できるようにする。

既存のユーザー名・ダッシュボード設定の保存方法とエラー処理を引き継ぐ。モードのチェック変更も同じ設定保存ボタンで保存し、保存成功後に表示へ適用する。初期値はOFF（通常モード）。拡張全体のON/OFFとは別の設定であることをチェック項目の説明に明記する。

OFF操作は単なるURL移動ではなく、既存の背景処理で転送ルール解除・状態保存を完了させてから通常noteホームへ移動する。モード設定やタグを初期化しない。

「通常のnoteを表示（拡張OFF）」は**設定タブの下部のみ**に配置する。全タブ共通の固定フッターには置かない。これは従来の「通常のnoteを表示（OFF）」と同じ操作であり、以降の「OFF操作」も拡張全体をOFFにすることを指す。

### 3.5 重度引きこもりモードの表示

```text
┌─────────────────────────────────────┐
│ ひきこもりnote                       │
│ [ 設定 ]                            │
│ 枠を超えたら落選したので、殻を作りました。│
│ [ ruminarのページ ]                 │
│ ─────────────────────────────────── │
│ noteユーザー名                      │
│ ダッシュボードを無効化              │
│ 記事の「あなたへのおすすめ」を非表示 │
│ 0.1.1モード（重度引きこもりモード）   │
│ [ ユーザー設定を保存 ] [ 状態を再確認 ] │

```

「0.1.1相当」は既存機能に絞ることを意味し、旧版そのものへのダウングレードではない。モード解除のチェック項目は引き続き設定タブに表示し、通常モードへ戻せるようにする。

### 3.6 記事の「あなたへのおすすめ」の表示設定

- `hideArticleRecommendations` は真偽値、既定false（表示）。チェックして「ユーザー設定を保存」を押すと反映する。未設定の旧データも表示のまま扱う。
- 適用条件は `enabled && hideArticleRecommendations`。通常・重度の両モードで有効とし、`legacyMode` とは独立させる。
- 対象URLはnote.comの `/ユーザー名/n/n英数字`（末尾スラッシュ・クエリ・フラグメントを許容）。投稿・編集・その他のページには適用しない。
- 記事本文外で、確認済みの「あなたへのおすすめ」h2と `aside[aria-label="記事"]` を直接の子領域に持つ専用divだけを余白ごと隠す。詳細なDOM境界は `docs/note-dom.md` に従う。本文内の同名見出し、コメント、記事操作、共通ヘッダーは変更しない。構造が不一致なら公式表示を維持する。
- DOMは削除せず専用属性とCSSで隠し、解除・全体OFF・対象外へのSPA遷移・処理停止で属性を外す。後から挿入されたおすすめ欄や既に開いている記事タブにも既存の変更監視・設定同期を通じて反映する。
- 背景処理の単一書き込みキューで `storage.local` に部分保存する。他の設定・タグ・並び順を保持し、保存失敗を成功と扱わない。別タブの更新で未保存の入力を上書きしない。
- 全体OFFでも選択は保持し、ON復帰・ブラウザ再起動後に再適用する。表示を隠す機能であり、おすすめの通信や取得を遮断するものではない。新しい権限・外部送信は追加しない。
- 受け入れ条件：既定表示、両モードの非表示、保存・復元、別タブ同期、後挿入、保存失敗、解除・全体OFFでの復帰、本文・コメント・対象外ページへの非干渉を確認する。

## 4. フォロー中・ハッシュタグ画面の共通サイドバー

記事画面の追加例外（F-212）：`isArticle` が認識する公開記事URLでは、通常モードかつ拡張ON・ビューポート幅1100px以上・表示中の `article#note-article` の左端が228px以上の場合、body直下に「フォロー中のTL」リンクを1つ追加する。リンクは左12px・上72px・幅200pxのfixed配置とし、本文・共通ヘッダーを書き換えない。リンク先は `https://note.com/following`。幅縮小、左余白不足、本文領域なし、重度モード、OFF、記事外へのSPA移動、処理停止で除去し、条件の復帰で再表示する。編集・投稿画面には追加しない。幅はCSSメディアクエリでも制限する。以前の「記事には追加しない」という条件は、本文外のこのリンクのみ例外とする。おすすめ非表示設定とは独立する。

### 4.1 表示内容

検索画面 `/search` と `/search/` にも同じ共通左サイドバーを適用する。クエリ・フラグメントの内容で対象を限定しない。通常モードかつ拡張ON時、確認済みasideが表示されている場合のみ差し替え、OFF・重度モード・画面離脱で元へ戻す。検索フォーム、結果一覧、記事・マガジン・クリエイター等の検索タブは変更しない。検索画面にはタグ追加ボタンを出さず、検索語を取得・保存・タグ登録しない。DOM境界は `docs/note-dom.md` の確認記録に従う。

通常モードかつ拡張ON時に、左メニューへ表示するのは**「フォロー中のTL」と登録済みタグだけ**。タグ順序は保存順。重度引きこもりモードでは独自サイドバーを表示しない。

```text
┌──────────────────────┐
│ フォロー中のTL        │
├──────────────────────┤
│ お気に入りタグ        │
│ # ComfyUI             │
│ # HandpickerSuite     │
│ # 創作大賞2026        │
│ # 縄文部              │
│ ...                  │
└──────────────────────┘
```

- フォロー中項目は、どちらの画面でも常に最上段に置く。
- 現在のURLに一致する項目を選択状態として視覚的に示す。
- 登録タグがない場合でも「フォロー中」は使える。
- 件数が増えた場合も閲覧・スクロールでき、右側の記事表示を狭めたり隠したりしない。
- サイドバーに「設定」リンク、ユーザーリスト、メンバーシップリストは追加しない。
- タグやフォロー中の**右側にある公式コンテンツは維持**。スキ・並び順・記事閲覧・フォロー等を改造しない。

例外として、利用者の追加指示により、タグ画面の「関連商品」枠を通常モードかつ拡張ON時に非表示にする。商品カードの `data-aicn-thing-card="true"` または `data-testid="aicn-thing-card"` と、同じ直近section内の `h2.sr-only` の「関連商品」見出しを確認できる場合に限る。記事を含むsectionや別見出しの領域は対象外とし、関連キーワードは維持する。section全体に専用の非表示属性を付けて余白も消し、DOM自体は削除しない。

左メニューの有無・ウインドウ幅に依存せず、対象のタグ画面で後挿入・再描画にも追随する。拡張OFF・重度モード・タグ画面からの離脱・構造不一致で非表示属性を除去する。これは表示の抑制であり、商品画像や外部リンク先への通信遮断は追加しない。

### 4.2 差し替え方式

- 変更するのは**対象画面の左サイドバー領域だけ**。note共通ヘッダー、ページ本体、右側の記事一覧には触れない。
- 元の左メニューは原則として削除せず、`enabled === true && legacyMode === false` で、独自サイドバーを安全に表示できる間だけ非表示にする。
- 拡張側のメニューは独立した要素として管理し、React等が管理する既存要素の内部を無理に書き換えない。
- 実ブラウザでDOM構造を確認した上で挿入先と非表示対象を決める。未確認のCSSセレクターを推測して本番実装しない。
- 対象DOMが存在しない・構造変更された場合は**無理に差し替えない**。公式画面を維持し、必要なら診断可能な状態を残す。
- 未ログイン画面・幅の狭い画面などで左カラムが存在しない場合も、公式表示を維持して追加サイドバーを省略する。独自の代替メニューを別の位置へ挿入しない。表示幅の変更・再描画で対象領域が現れた場合は、確認済みの条件に従って再適用する。
- SPA遷移、戻る・進む、動的DOM再生成、別タブの設定変更、拡張OFF/ON、モード変更に対応する。モード有効化または拡張OFFでは、既に表示中の独自サイドバーと非表示指定を除去して公式メニューを復帰させる。モード解除かつ拡張ONでは対象DOMを確認して再適用する。URLや記事一覧には介入しない。
- 重複挿入、無限MutationObserverループ、切り替え時の表示残りを防止する。
- CSSは拡張専用の識別子でスコープを限定し、他のnote要素への副作用を避ける。

## 5. 任意のクリエイターページへの帰還ボタン

### 5.1 目的と位置

自分のページだけでなく、**他ユーザーのプロフィールからもフォロー中画面に直接戻れるようにする**。

位置は、**カバー画像の下にある左カラムの先頭、ユーザーのアイコン・名前・紹介文よりも上**。マガジンなどの長いリストが後続してもボタンが下に流されない。

```text
┌──────────── 左カラム ────────────┐
│ [ フォロー中のTL ]               │ ← 先頭
│                                  │
│ 〔アイコン〕 ユーザー名            │
│ 自己紹介・フォロー操作等（純正）   │
│                                  │
│ マガジン一覧等（純正）             │
└──────────────────────────────────┘
```

### 5.2 動作

- ボタンのリンク先は常に `https://note.com/following`。
- 表示条件は `enabled === true && legacyMode === false` とする。重度引きこもりモードでは追加しない。
- ブラウザの履歴に依存する「戻る」動作ではない。
- ボタン以外のプロフィールの機能、フォロー操作、各タブ、マガジン表示は変更しない。
- 対象は**全ユーザーのクリエイターページ**。プロフィール左カラムが確認できるページに限って追加する。
- プロフィール情報の上であって、note全ページ共通の上部ヘッダーには挿入しない。
- 遷移やDOM再生成時にボタンを二重挿入せず、拡張OFFまたは重度引きこもりモードへの切り替えで除去する。モード解除かつ拡張ONで対象DOMがあれば再適用する。
- ウインドウ幅だけを理由に帰還ボタンを非表示にしない。狭い幅でプロフィール情報が縦並びになっても、確認済みの同じプロフィール領域が表示されていれば、その先頭へ追加する。設定ボタンに近い枠・角丸・中央寄せ・全幅のリンク表示とする。プロフィール領域自体を確認できない・非表示の場合は省略し、別の位置へ推測で挿入しない。

## 6. 設定・データモデル

### 6.1 既存設定と新規項目

v0.1.1の保存形式を維持したまま、**`favoriteTags`**、**`legacyMode`**、**`hideArticleRecommendations`** を追加する。モードフラグ名は本書では `legacyMode` とする。実装時に既存の命名規約に合わせる場合も、拡張全体の `enabled` と分離する。

```ts
// 設計上の概念型。既存コードをTypeScriptへ移行する指示ではない。
type Settings = {
  enabled: boolean;            // 既存
  noteUserId: string;           // 既存
  dashboardDisabled: boolean;   // v0.1.1既存、未設定時false
  hideArticleRecommendations: boolean; // v0.2.0新規、未設定時false。両モード共通
  favoriteTags: string[];      // v0.2.0新規、未設定時[]
  legacyMode: boolean;         // v0.2.0新規、未設定時false。拡張全体のON/OFFとは独立
};
```

- ストレージは既存の `storage.local`。
- v0.1.1からアップグレードしたとき、`favoriteTags` が未定義なら空配列と解釈する。
- `legacyMode` が未定義ならfalse（通常モード）と解釈する。ブラウザ再起動後も保存済みの選択を維持する。
- 保存済みの `enabled`、`noteUserId`、`dashboardDisabled` を消さない。設定の部分更新方式・単一書き込み管理を維持する。
- フォロー中・タグ画面のサイドバーとメインタブは**同じ `favoriteTags`** を参照し、別々のコピーを恒久保存しない。
- 他ブラウザへの同期、新たな外部サーバー、認証情報の収集は追加しない。
- モードの有効化・解除や拡張OFFを理由に、タグ一覧・並び順・その他のv0.2.0設定を初期化・上書きしない。通常モードに戻したら保存済みの値をそのまま表示へ反映する。重度引きこもりモード中にタグ一覧の別コピーや空配列を保存しない。

### 6.2 アクセス時の動作

- 専用ホームは保存データを読み込み、通常モードならメイン、重度引きこもりモードなら設定を最初に表示する。
- タグ管理の変更保存が成功したら、ホーム内の表示へ反映する。
- 開いている別タブに対しては、`storage.onChanged` または既存APIアダプター相当の仕組みで更新する。
- 拡張OFFまたは重度引きこもりモードの場合、note上の左メニュー置換や帰還ボタンなどの追加UIを適用しない。ダッシュボード無効化と通常ホーム転送は第6.6節の独立した条件で扱う。

### 6.3 タグ操作の直列化と競合

- タグ配列全体を画面側から保存する方式は使用しない。画面は次の操作を、既存APIアダプターを通して背景処理へ送る。メッセージ名は実装時に既存規約と整合させてよい。

```js
{ type: "ADD_TAG", tag: "ComfyUI" }
{ type: "REMOVE_TAG", tag: "ComfyUI" }
{ type: "MOVE_TAG", tag: "ComfyUI", beforeTag: "AI" }
{ type: "MOVE_TAG", tag: "ComfyUI", beforeTag: null } // 末尾へ移動
```

- タグ操作と既存設定の保存は、同じ背景処理の単一キューで直列化する。各操作の実行時に保存済みの最新状態を読み、対象の変更だけを適用する。保存完了または失敗を確認してから次の操作へ進む。
- モード変更も同じキューに統合する。重度引きこもりモード中はタグの変更要求を受け付けず、最新状態を返してモード変更を通知する。切り替え直前のタグ操作はキューの実行順で扱い、先に完了した変更は保持する。モード保存後に実行するタグ操作は保存せず拒否する。
- ADDは最新一覧の末尾へ追加する。同一保存値が既にあれば重複エラーとする。A・Bが異なるタグを同時追加しても両方残す。順序は背景処理で実行した順とする。
- REMOVEはタグの保存値を指定する。MOVEは移動するタグと移動先のタグの保存値を指定する。古い配列のインデックスは送らない。
- MOVEは最新配列から対象を取り出して `beforeTag` の直前へ移す。`null` は末尾を示す。自分自身への移動は変更なしとする。
- 削除・移動対象または移動先が既に削除されていた場合は、競合として通知し、その操作による保存は行わない。最新一覧を確認して再操作できるようにする。別タブが保存した変更を古い画面の配列で巻き戻さない。
- 同一タグへの複数の移動は、それぞれ実行時の最新配列へ受信順に適用する。古い画面で意図した一覧全体の並び順を固定・復元する機能は設けない。
- 保存完了後の結果応答と既存のストレージ変更イベントを使って画面を更新する。設定保存・削除・並べ替えは自拡張の専用ホームに限定する。例外としてF-211の表示中タグの追加のみ、検証済みnoteタグ画面のコンテンツスクリプトから受け付ける。

#### タグ画面の追加ボタン

- 通常モードかつ拡張ON時、確認済みの共通左メニューに「タグをお気に入りに追加」ボタンを、お気に入り一覧の前に表示する。`/tag/` と `/hashtag/` のURLから1セグメントをデコードし、既存ルールで正規化する。大文字小文字・全半角は維持する。
- 登録済みなら追加ボタンを表示しない。別タブ等でお気に入りから削除された場合は追加ボタンを再表示する。空タグ・不正な保存データでも追加を無効にし、破損データの警告を表示する。フォロー中・プロフィール・記事では追加ボタンを出さない。左メニューがない場合は別の場所へ追加しない。
- 送るメッセージは `add-current-tag` のみ。背景処理は自拡張ID・最上位フレーム・タブ・送信元URLを検証し、そのURLからタグ名を導出する。メッセージ内の任意タグ名を信用しない。note上からの設定保存・タグ削除・並べ替えは許可しない。
- ホームと同じ背景キューでADDを実行し、最新の設定が拡張ON・通常モードであることを再確認する。同時追加・重複・保存失敗は既存ルールに従い、成功後だけ登録済みへ更新する。タグ配列全体を送信・上書きしない。追加権限なし。
- 保存中は追加を無効化。既知の失敗はその旨を表示して再試行できる。結果未確認では別タグに移動しても追加を止め、自動再送せず「状態を再確認」で保存済みデータを再取得する。失敗時は成功表示をしない。
- 受け入れ条件：日本語タグ・両URL形式・クエリ・SPA移動・連打防止・重複・他タブ同期・保存失敗・結果未確認・OFF/重度切り替え・送信元検証を確認する。

### 6.4 最小限の正規化と不正な保存データ

- タグ入力の前後の空白を取り除き、先頭の半角 `#` を除去する。除去後にも前後の空白を取り除き、空文字になった場合は拒否する。
- 大文字小文字・全角半角・内部の空白は変換しない。Unicode正規化による自動統合も行わない。重複は正規化後の文字列の完全一致だけで判定する。

| 入力 | 保存値 |
|---|---|
| `  #ComfyUI  ` | `ComfyUI` |
| `#創作大賞2026` | `創作大賞2026` |
| `ComfyUI` | `ComfyUI` |
| `comfyui` | `comfyui`（上のタグと別項目） |
| `ＡＩ` | `ＡＩ` |
| `AI` | `AI`（上のタグと別項目） |

- URL生成時は保存値をタグ名の1セグメントとしてエンコードする。保存値にエンコード済みURLや表示用の `# ` を格納しない。
- 保存済み配列に不正な型・空項目・重複等が混在している場合は、利用できる正常項目を順番どおり残し、異常を報告する。読み込みだけでストレージを空配列へ上書きしたり、破損項目を無言で消したりしない。
- `favoriteTags` 自体が配列でない場合も「未設定」と区別して異常を報告し、元の保存値を自動で置き換えない。正常な既存設定は引き続き利用できるようにする。
- 異常データのあるタグ一覧への書き込みは停止し、明示的な修復方法を案内する。破損項目の自動修復や独自のバックアップ基盤は今回の機能範囲に含めない。タグ以外の設定保存でも、不正なタグデータを空配列に変えて消さない。

### 6.5 背景処理の停止・再起動と保存結果

- 同一の背景実行環境内ではPromise等の単一キューを使う。ChromiumのService WorkerやFirefoxの背景処理のメモリー上の配列を、保存データの正本としない。
- 背景処理の再起動後は `storage.local` の最新状態を読み込み、新たに受け付けた操作を適用する。永続操作キュー・独自DB・独自トランザクション基盤は追加しない。
- 操作を受信しただけで成功を返さない。`storage.local` の保存完了を確認してから成功応答を返す。通常の保存失敗時は成功表示を出さず、以前の確認済み状態を維持する。
- 保存が完了していても、停止や接続切断で成功応答だけ失われる可能性がある。その場合は成功・未保存のどちらとも即断せず、結果未確認として表示し、背景処理への再接続後に保存済みの最新状態を取得する。操作を無条件に自動再送しない。
- 最新状態を再取得するまでタグ変更操作を停止し、入力途中の文字列を保持する。復旧後は確認できた一覧を表示して利用者が再操作できるようにする。背景処理に届かなかった要求の自動復元や、必ず1回だけ実行される保証は設けない。
- 既存ON/OFF等の転送ルール更新・保存失敗時のロールバックは維持する。タグ操作の失敗・再起動後も、既存設定を初期化しない。

### 6.6 モードと拡張ON/OFFの独立性

| 拡張全体 | モード | 専用ホームを開いた場合 | note上の0.2.0追加UI | 通常ホーム転送・ダッシュボード制限 |
|---|---|---|---|---|
| ON | 通常（`legacyMode: false`） | 3タブ、自分のページ＋フォロー中。キャッチコピーなし | 確認済みの対象DOMへ適用 | 通常ホームは転送。ダッシュボードは設定次第 |
| ON | 重度（`legacyMode: true`） | 設定のみ。タブ内容の先頭にキャッチコピーと自分のページへのクイックアクセス | 除去して公式表示へ戻す | 通常ホームは転送。ダッシュボードは設定次第 |
| OFF | いずれも保持 | 保存済みモードに応じたホーム構成と、拡張OFFの状態を表示 | 適用しない | 両方とも解除。OFF操作後は通常noteホームへ移動 |

- モードの保存は `enabled` を変更しない。全体のON/OFF操作は `legacyMode` を変更しない。拡張アイコンによるON復帰でも保存済みモードを維持する。
- モードの有効化・解除は設定保存成功後に確定する。通常の保存失敗では以前の実効モード・表示を維持し、エラーを表示する。応答喪失時は第6.5節に従い最新状態を再取得し、無条件に再送しない。
- 設定保存は利用者が変更した項目だけを部分更新し、モード変更と他タブのON/OFF・ユーザー名・ダッシュボード設定を上書きし合わない。同じモード設定の同時変更は背景処理で実行した順に適用する。
- 成功したモード変更をストレージ変更イベントで、開いている全専用ホーム・フォロー中・タグ・プロフィールのタブへ反映する。未保存の入力は保持し、非表示になったタブへフォーカスや選択状態を残さない。
- モード変更だけではnoteタブを遷移・再読み込みさせない。公式ヘッダーは変更せず、独自サイドバー・帰還ボタンの除去と公式表示の復帰を行う。既存ダッシュボード制限による転送は維持する。
- 共通サイドバーと帰還ボタンの有効条件は `enabled && !legacyMode`。通常ホーム転送は `enabled`、ダッシュボード制限は `enabled && dashboardDisabled` とし、モードから独立させる。

## 7. 既存のv0.1.1から守るべきもの

1. `https://note.com/` の文書アクセスを拡張専用ホームへ転送する既存動作。
2. 拡張アイコンによるON復帰、設定からのOFF、失敗時のロールバック。
3. `dashboardDisabled` による `/dashboard` および配下への転送・リンク非表示。拡張ONなら通常・重度の両モードで保存済み設定に従い、拡張OFFで解除する。
4. OFFでは開いているnote画面の公式メニューを再表示し、拡張が追加したサイドバー・帰還ボタンを除去する。設定からのOFF操作後の移動先は従来どおり `https://note.com/`。直前のURLへ戻す機能は追加しない。ON復帰は従来どおり拡張アイコンから専用ホームを開き、モードを含む設定値は保持する。重度引きこもりモードへの切り替えだけでは拡張をOFFにしない。
5. Chrome/Edge/Firefox用の既存ビルド・Manifest生成、`src/platform/browser-api.js` のAPI差分吸収。
6. 日本語ロケール、配布パッケージ、既存の検証スクリプト。
7. 投稿・編集・決済・認証・記事本文など、v0.1.1で触っていない画面を壊さない。

現行の実装内容とこの文書が衝突する場合、**既存機能を破壊する変更を勝手に実施せず、差分を報告**する。

## 8. 非機能要件

### 8.1 軽量・保守性

- 本リリースのためにタグフィードの収集・定期更新・独自記事キャッシュを実装しない。
- 既存ページへの余計なネットワーク要求を増やさない。タグリストはローカル設定だけで描画する。
- DOM監視は対象領域に限定し、更新が必要なときだけ最小限の処理を行う。
- サイドバー差し替えの共通処理を再利用し、フォロー中画面とタグ画面に同じロジックを重複実装しない。

### 8.2 安全性・アクセシビリティ

- タグ名・ユーザー名は信頼できない文字列として扱い、HTML文字列として無検証に挿入しない（`textContent` 等を使用）。
- タグURLはエンコードし、`javascript:` 等の不正URLを生成しない。
- キーボードでタグの追加・削除・順序変更・リンク操作ができるようにする。
- スクリーンリーダー向けのボタン名と現在選択項目の状態を適切に設定する。
- モード切り替えにより選択中のタブが非表示になる場合は、選択を設定タブへ移し、非表示になる要素内にフォーカスがあれば設定タブ等の表示中の要素へ移す。モードの表示名と拡張全体のON/OFF状態を区別して通知する。
- ブラウザ拡張の追加権限を最小化し、要求する場合は理由を明記する。
- noteが変更したDOMに誤適用する危険がある場合は、強引な削除ではなく公式画面を残す。

## 9. 実装前の確認事項（Codexで調査）

画面設計は確定。以下は**技術検証項目**であって、新しい機能提案ではない。

1. `/following` の左メニューの実DOMと、その外側のレイアウト境界。
2. `/hashtag/<タグ>` および `/tag/<タグ>` の左メニューの実DOM、正規遷移URL。
3. クリエイターページの左カラム先頭への安全な挿入位置。自己ページ・他人ページ・マガジンの多いページを含む。
4. noteのSPA遷移・後挿入・再描画で、注入した要素がどう扱われるか。
5. Chrome/Edge/FirefoxでのContent Script・CSSの適用タイミングと解除方法。
6. 幅の狭い画面など、左カラムが存在しない表示での安全なフォールバック。

**DOMが未確認の間は仮のセレクターを本番用コードに埋め込まないこと。** 実環境で確認できない箇所は未検証として記録し、検証手順を文書化する。
