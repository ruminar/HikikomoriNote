# ひきこもりnote v0.2.4 社会復帰モード 設計・実装仕様

- **対象**：`ruminar/HikikomoriNote`
- **基準**：0.2.3（タグ `0.2.3`。作者表示管理と設定JSON形式3を含む）
- **対象バージョン**：0.2.4
- **状態**：実装済み・実ブラウザ受け入れ確認待ち（2026-10-31）
- **目的**：既存の「ひとみしり」「重度ひきこもり」に「社会復帰」を追加し、公式ホームと公式メニューを維持したまま、必要な閲覧支援機能を利用できるようにする。

## 1. 設計方針

1. **3モードは相互排他**とし、チェックボックスではなくセレクトボックスで切り替える。
2. **拡張全体のON/OFFはモードとは別**とする。OFF時は3モードのいずれを保存していてもnote公式表示を維持し、既存の拡張による変更を停止・復元する。
3. 社会復帰モードは、**`https://note.com/` の通信前転送を行わず、note公式ホームをそのまま表示**する。
4. 社会復帰モードでは、**公式左メニューの差し替え、独自の狭幅メニューを停止**する。一方、記事表示に対する既存の非表示設定や、本文を妨げない追加導線は維持する。
5. 重度ひきこもりモードでは、**記事横の作者導線だけを新たに有効化**し、TL導線は引き続き無効とする。
6. モード変更でお気に入りタグ・4グループ・他の表示設定を削除しない。見せないモードでは編集UIを隠す。
7. **社会復帰note（別アドオン）の有無に依存しない**。検出・通信・協調制御は本変更の範囲外。
8. 既存のテスト・ブラウザ対応・権限を原則維持し、実装を必要以上に広げない。

## 2. モード定義

| 内部値 | 表示名 | 趣旨 |
|---|---|---|
| `normal` | 通常モード（ひとみしりモード） | 専用ホームと独自ナビゲーションを使い、見たい記事を自分で選ぶ |
| `severe` | 重度ひきこもりモード | 公式ホームを避け、独自のタグ・TLナビゲーションも表示しない |
| `social` | 社会復帰モード | 公式ホームと公式ナビゲーションを使いながら、個別の閲覧支援機能は使う |

- 新規インストール時の既定値：`normal`。
- モード選択は拡張ON時の挙動を決める設定であり、拡張OFFを第四のモードとして扱わない。
- モード変更は既存の「ユーザー設定を保存」で確定させる。未保存の選択は他画面に反映しない。

## 3. 機能マトリクス（確定した要求）

| 機能 | `normal` ひとみしり | `severe` 重度 | `social` 社会復帰 |
|---|---|---|---|
| `note.com/` の公式ホーム | **専用ホームへ転送** | **専用ホームへ転送** | **公式ホームを表示** |
| 公式左メニュー | 独自ナビゲーションへ差し替え | 変更しない | **変更しない** |
| 狭幅時の独自☰メニュー | 対象画面で使用 | 非表示 | **非表示** |
| note公式ロゴ | `noteLogoBrowserBack` 設定に従う | 同左 | **公式のリンク動作に固定** |
| ロゴ隣の設定歯車 | ロゴ戻り設定ON時 | ロゴ戻り設定ON時 | **拡張ONなら常時表示**（確認済み公式ヘッダーに限る） |
| 設定画面の「お気に入りタグ」編集 | 表示・操作可能 | 隠す | **隠す** |
| 保存済みタグ・グループ | 保持 | 保持 | **保持** |
| 有料・メンバーシップ記事カード非表示 | 設定に従う | 設定に従う | **設定に従う** |
| 記事内「チップで応援する」枠非表示 | 既存設定に従う | 同左 | **同左** |
| 記事下の「あなたへのおすすめ」非表示 | 設定に従う | 設定に従う | **設定に従う** |
| **記事横の作者ページ導線** | 表示 | **表示（今回追加）** | **表示** |
| **記事横の「フォロー中のTL」導線** | 表示 | **非表示** | **表示** |
| 公式ヘッダーの検索欄クリアボタン | 表示 | 表示 | **表示** |
| ダッシュボード無効化 | 既存設定に従う | 同左 | **同左** |
| 拡張OFF | すべての独自処理を停止 | 同左 | 同左 |

ここでいう「表示」は、**既存のDOM識別・画面幅・余白・記事ページ判定が成立する場合のみ**を意味する。記事横の固定導線を狭幅画面へ無理に表示する変更はしない。

### 3.1 既存機能の取り扱い（実装時の整理）

- **検索結果の「記事」タブへ戻すと新着順にする処理**：左メニュー差し替えと独立しているため、`normal` と `social` で継続する。`severe` は現状どおり対象外。
- **タグ画面の関連商品枠非表示**：`normal` での既存動作を維持し、`social` でも継続する方針とする。`severe` では現状どおり停止する。実際の適用対象とDOM条件は現行実装から変更しない。
- **プロフィール画面の「フォロー中のTL」追加導線**：公式プロフィール情報を置換しない独立した追加リンクなので、`normal` と `social` で継続する方針。`severe` は現行どおり停止。*現行実装ではメニュー構築処理と一体化しているため、社会復帰モード実装時は左メニュー置換とは別の判定に分ける。*
- **タグ画面の「お気に入りに追加」ボタン**：現行は独自左メニュー内部の機能。`social`・`severe` では編集UIを使わない方針に合わせて出さない。タグの保存データは維持する。
- **設定の移行**：全モードで表示する。お気に入りタグ編集を隠すモードでも、設定JSONの書き出し・読み込みはできる。
- **記事プレビュー**：記事横の作者/TL表示は公開記事と同じモード判定を使い、既存の作者検出・アクセスキー保護の条件を維持する。

## 4. 設定画面

### 4.1 モード選択UI

既存の「重度ひきこもりモード」チェックボックスを廃止し、`<select>` に置き換える。

```text
動作モード
┌──────────────────────────┐
│ 通常モード（ひとみしりモード）  ▾ │
└──────────────────────────┘
候補：
  通常モード（ひとみしりモード）
  重度ひきこもりモード
  社会復帰モード
```

選択値に応じて短い説明文を表示する。

- `normal`：「専用ホームとお気に入りタグから、見たい記事を選んで閲覧します。」
- `severe`：「公式ホームを開かず、タグやTLの独自メニューも停止します。作者ページへの導線は残します。」
- `social`：「note公式ホームと左メニューを使用し、記事の非表示設定や追加導線は使います。」

### 4.2 ホーム設定画面の表示

- `normal`：従来どおり、お気に入りタグ・設定・設定の移行を表示。
- `severe`：従来のキャッチコピー中心の初期表示を維持。お気に入りタグ編集は非表示。設定・設定の移行は利用可能。
- `social`：**初期表示を設定画面**とし、お気に入りタグのナビゲーション項目と編集パネルを隠す。設定・設定の移行は利用可能。
- `social` に切り替えて保存した場合、`home.html` は設定画面として利用できる。**「note公式ホームへ戻る」明示的なリンク**を用意し、ユーザー設定を保存しただけで意図せず画面遷移はしない。
- 隠した編集UIへ `#tags` 等で直接アクセスしても編集させない。`social` では設定画面へ、`severe` では重度モードの既存初期表示へ戻す。
- 「通常のnoteを表示（拡張OFF）」は維持する。**社会復帰モードへの切替と拡張OFFを混同しない**。
- モード変更時にフォーカスが隠れる要素上に残らないよう、安全な可視の要素へ移す。

### 4.3 歯車とロゴ

- 現行の歯車は `noteLogoBrowserBack` と連動して表示される。新条件は `enabled && (mode === 'social' || noteLogoBrowserBack)`。`social` の場合のみロゴ戻り設定を無視する。
- `social` の歯車リンクは **`home.html#settings`** を開く。設定編集に入るためにタグ画面を経由させない。
- `normal`・`severe` での歯車表示条件およびロゴの戻る動作は維持する。
- `social` では `noteLogoBrowserBack === true` が保存されていても、ロゴクリックを奪わない。値は削除せず、他モードへ戻したら再び有効とする。
- 「常時表示」は、現行の `isOfficialHeaderLogo` / `logoContainer` が安全に識別できる**公式ヘッダーがある場合**を指す。未知構造では無理に挿入しない。
- 拡張OFFでは歯車も独自クリック制御も解除する。

## 5. 記事横の作者導線とTL導線の分離

### 5.1 表示条件

0.2.3では `syncArticleFollowing()` が `!settings.legacyMode` でTLと作者をまとめて除去していた。0.2.4は以下の別判定を使用する。

```text
記事横の共通表示条件：
  拡張ON
  ＋ 公開記事または共有プレビュー記事
  ＋ article#note-article が確認できる
  ＋ 幅 1100px 以上
  ＋ 記事左余白 228px 以上
  ＋ その他、現行の安全なDOM判定

作者リンク：共通条件を満たせば全3モードで表示（作者を識別できた場合）
TLリンク：共通条件を満たし、mode が normal または social なら表示
```

- 作者が検出できなければ作者リンクだけ省略する。TLリンクの有無とは独立。
- `severe` でTLリンクがない場合、作者リンクを**TLリンクの位置に繰り上げる**。既存の固定位置（TLが上、作者が下）からの変更は必要最小限とする。
- note公式の作者表示や固定サイドプロフィールと重複・重なりがないよう、現行の `syncSideProfiles()` に対応するオフセット判定を修正する。
- 公開記事とプレビュー記事で同じ表示条件を使い、本文やコメントには独自UIを差し込まない。
- SPA移動、画面幅変更、拡張OFFで両リンク・位置調整を適切に復元する。

## 6. ホーム転送・ダッシュボード転送

**重要：ホーム転送はコンテンツスクリプトだけでなく `declarativeNetRequest` の動的ルールにも存在する。**

- `normal` と `severe`：既存どおり `note.com/` のメインフレームを `home.html` へ転送し、対応する非メインフレームの通信ルールも維持する。
- `social`：`note.com/` 用の転送ルール・ブロックルールを**両方除去**する。公式ホーム表示とその通常通信を妨げない。
- `dashboardDisabled`：全3モードで既存の設定どおりに適用する。社会復帰モードでもONならダッシュボードは専用画面へ転送し、ボタン非表示を維持する。
- `enabled === false`：ホーム／ダッシュボード両方の動的ルールを除去する。
- クリック・SPA・Navigation API・ロード後チェックでも、`social` の公式ホームへの移動を奪わない。
- モード変更時は**動的ルール適用と設定保存の整合性**を維持する。保存失敗時は既存のロールバック・エラー処理を活かす。ブラウザ再起動や拡張更新後も保存モードを再適用する。

## 7. 左メニュー・追加導線

- 独自ナビゲーションの有効条件は **`enabled && mode === 'normal'`** とする。
- `severe` と `social` では、公式サイドバーを隠すCSSクラス、置換用ナビゲーション、狭幅☰パネル、関連する後処理を解除する。
- モードを変えた瞬間、旧モードが付けた非表示属性・クラスを**確実に除去**し、note公式の左メニューを復元する。
- 左メニュー以外の既存機能（検索欄クリア、記事下おすすめ非表示、有料カード/チップ枠非表示、記事横導線、関連商品枠、検索結果記事タブの新着化）は、それぞれ独立した条件で実行する。**メニューを止めるために `update()` を丸ごと早期returnして、これらまで止めないこと**。
- プロフィール画面のTL追加リンクは `social` でも有効。ただし既存の独自メニュー共通処理から切り離し、**公式プロフィール情報の表示を変更しない**。
- 社会復帰モードは公式タグリンクの `href` を書き換えない。タグ検索の全面書き換えは別製品「社会復帰note」の担当とし、未導入でも本拡張は単独動作する。

## 8. データ構造・設定移行

### 8.1 内部状態

```javascript
// 設計上の状態例。既存の全項目は保持する。
{
  enabled: true,
  mode: "normal",           // "normal" | "severe" | "social"
  noteLogoBrowserBack: false,
  dashboardDisabled: false,
  hidePaidArticles: false,
  hideArticleRecommendations: false,
  // noteUserId、tagGroups、selectedTagGroupId、更新番号などは従来どおり
}
```

- `legacyMode: boolean` は新規保存形式から廃止し、`mode` を単一の正本とする。
- 4グループのお気に入りタグ構造（`tagSchemaVersion: 2`、タグ・順序・名前・選択グループ）は変更しない。
- `noteLogoBrowserBack` など、社会復帰モードでは一時的に無視する設定も、値を保持する。
- 未知のモード値・未定義は `normal` として読み込む。旧ストレージの `legacyMode` は自動変換しない。読込だけでは保存せず、次の保存時に `mode` を記録し旧フラグを除く。タグ・作者設定などは保持する。旧重度設定は通常として起動するため、利用者がモードを選び直す。

### 8.2 設定JSONの取り扱い

- 新しいJSON書き出しには `mode` を含め、廃止する `legacyMode` は含めない。
- 厳格な入力検証を維持する。未知キー・未知モード値は受け付けない。
- **形式3を維持**し、`mode` の `normal`／`severe`／`social` をすべて受け付ける。0.2.3で書き出した通常・重度のJSONもそのまま使える。0.2.3へ社会復帰JSONを持ち込むと、旧版側で未対応として拒否される。
- 既存の明示的な形式1／2インポートは維持する。JSON検証内だけで `legacyMode` を `normal`／`severe` に変換する。ストレージ自動移行とは別であり、新しい移行レイヤーは追加しない。
- 形式1は作者設定を持たないため、既存どおり解除を確認してから全置換する。形式2／3は作者設定も復元する。
- 保存済みタグ・グループ・作者表示ルール・各設定はモード変更で削除しない。更新番号は従来どおり管理し、保存キュー・競合検出・保存失敗時のDNR復旧を維持する。
- 通常設定保存・タグ操作・作者操作でも、保存したオブジェクトに廃止フラグを残さない。破損したタグ／作者の元データは従来どおり保持し、その編集を止める。

## 10. テスト・受け入れ条件

1. **初期状態**：新規インストールでは `normal`、従来の専用ホームと左メニューが使える。
2. **3モード排他**：セレクトで1つだけ選択でき、保存・再起動後も同じモードになる。
3. **社会復帰ホーム**：`social` で `https://note.com/` を開くと公式ホームが表示される。ホーム用動的ルールが残っていない。
4. **重度／通常ホーム**：`normal`・`severe` に戻すと、既存のホーム転送が再び正しく動く。
5. **公式左メニュー**：`social`・`severe` では公式左メニューが残り、独自メニューが消える。`normal` に戻すと独自メニューが復活する。
6. **ロゴ動作**：`social` では保存値 `noteLogoBrowserBack=true` でも公式ホームへ遷移する。`normal`・`severe` に戻すと設定値どおりの挙動へ戻る。
7. **歯車**：`social` ではロゴ戻り設定OFFでも歯車が表示され、`home.html#settings` を開ける。拡張OFFでは消える。
8. **タグ編集**：`social`・`severe` ではタグ編集画面へ行けない。両モードから `normal` に戻すと、タグ・グループ名・並び順が保持されている。
9. **重度の作者導線**：記事／プレビューの既存レイアウト条件を満たすと作者リンクだけ表示され、TLリンクは出ない。作者リンクの位置が正しい。
10. **通常・社会復帰の作者/TL**：条件を満たす記事・プレビューで両方表示される。作者を特定できない場合はTLだけ残る。
11. **非表示設定**：3モードとも、有料記事/チップと記事下おすすめを設定どおり非表示・復元できる。
12. **検索・関連表示**：検索欄クリアは3モード、記事タブ新着戻しとタグ関連商品非表示は `normal`・`social` で機能する。
13. **プロフィール導線**：`social` でも既存の追加TLリンクが表示でき、公式プロフィール情報を隠さない。`severe` では既存動作を維持。
14. **ダッシュボード**：3モードで既存の無効化ON/OFFが機能し、ホーム転送用ルールと混同しない。
15. **拡張OFF**：全モードからOFFにでき、独自メニュー・歯車・リンク・非表示クラス・転送ルールが解除される。
16. **動的DOM**：SPA遷移・DOM再生成・リサイズ・設定変更で重複挿入や隠しっぱなしが生じない。
17. **設定移行**：新形式の書き出し→再読込が成功し、モード・タグ・表示設定を再現する。旧JSONを拒否する場合は理由を表示する。
18. **対応ブラウザ**：Chrome / Edge / Firefox Desktop / Firefox Android。手動検証済みと自動テスト結果を区別して記録する。

## 11. 非対象

- 新拡張「社会復帰note」のインストール有無の検出や、拡張機能間のメッセージ通信。
- note公式タグリンクの全面書き換え、右クリックメニュー改造、検索ボタンの新設。
- タグ・フォロー中のTLの独自データ取得、本文の自動収集、AI処理。
- 新たな課金非表示条件、プロフィール管理、ダッシュボード統計取得。
- ストアへの自動申請、リリース・タグ作成。
- 旧バージョンとの完全な移行互換性を確保するためだけの複雑な処理。

## 12. 実装判断と確認状況

- 内部設定は `mode` を正本とする。旧ストレージの自動移行は追加せず、未設定・不正値は通常とする。旧JSONの明示インポートだけ既存機能として残す。
- 共通判定は `modeOf`／`usesTags`／`usesFollowing`／`usesLogoBack` の小さな関数にまとめた。汎用モードエンジン・新たな権限・ライブラリ・通信先は追加しない。
- 社会復帰の歯車は `home.html#settings`。プロフィールでは0.2.3の作者管理への直行（`#authors`）を優先し維持する。
- プロフィールTL追加だけ既存の挿入処理を再利用し、公式情報の非表示処理はプロフィールでは実行しない。
- 重度の作者リンクには `hikikomori-note-article-author-only` を付けてtop 72pxへ上詰め。公式固定プロフィールは、作者だけならtop 124px、作者＋TLならtop 184pxへ移す。リンクがなければ位置調整を解除する。
- `document_start` の設定取得前には、モード不明のまま公式メニューを隠さない。直接の `storage.local` 読込が終わり通常と判明したら、従来のSSRレイアウト親へクラスを付けて後挿入をCSSで制御する。追加の待ち時間・監視機構は作らない。通常モードの再読込時のちらつきは実ブラウザで確認する。
- 構文チェックおよび自動テスト200件が成功。自動テストでは、DNRのモード別境界・保存と復旧・JSON・動的DOM・狭幅UI撤去・重度作者リンク・設定UI・独立した非表示機能を確認する。
- Chrome／Edge／Firefox Desktop／Firefox Androidの実拡張受け入れは未実施。特に通常⇔社会復帰のメニュー復元、狭幅、ロゴクリック、ブラウザ再起動を確認する。
- リリース・タグ・コミット・ストア申請は今回の実装作業に含めない。

## 0.2.3の先行変更の記録（履歴）

0.2.3で先行したのは外部の設定JSONだけ。schemaVersion=3、modeはnormal／severe／socialとし、legacyModeは書き出さない。0.2.3ではnormal／severeを既存の内部legacyModeへ変換し、socialは未対応として保存前に拒否する。形式1／2の明示的な読み込みは維持する（本書8.2節の旧JSON非対応可という案より、この確定事項を優先する）。

社会復帰の実装時も、項目構成が同じなら形式3と同じmode値を使用する。0.2.3では内部storageのmode化、コンボボックス、ホーム転送・画面動作の変更は行わなかった。0.2.4では本書のとおり実装する。
