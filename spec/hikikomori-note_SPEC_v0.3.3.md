# ひきこもりnote 0.3.3 記事のお気に入り（開発版）

2026-11-12。0.3.2を基準に、お気に入りの5種類目として記事を追加する。実装前に現行保存処理・JSON互換・おしゃべりnoteを確認。コミット・Push・タグ・公開は行わない。記事本文・画像・投稿日は保存せず、追加APIも呼ばない。

## 保存と識別

保存キーhikikomoriNote.settings.v2、4グループ、既存のtags配列と更新番号・競合制御を維持する。記事は {"type":"article","articleId":"n123","url":"https://note.com/example/n/n123","title":"記事のタイトル"}。既存isArticle()を使い、https://note.comの公開記事のみ。認証情報付きURL・プレビュー・外部URLは拒否し、URLの記事IDとarticleIdの一致を要求する。保存URLはquery・hash・末尾スラッシュなし。タイトルは空白除去後の1〜500文字、制御文字なし。

キーはarticle:記事ID。作者やURLパラメータ・タイトルが違っても同じ記事IDは同一記事。記事は4グループ全体で重複登録を防ぎ、移動は既存TRANSFER_TAGを再利用する。手動JSONの重複は既存項目を優先し、残りを無視理由に表示する。既存種別の重複規則は変えない。

記事を含む保存はtagSchemaVersion=6。旧2〜5を引き続き読め、記事追加前の保存形式は不要に変更しない。未知・破損した保存形式を上書きしない保護は維持する。記事を含む設定書き出しはschemaVersion=8、記事を含まない場合は従来の7を維持する。旧1〜7・形式名や版番号省略・未知版の部分読み込みは維持する。記事を含めた往復・省略保持・不正項目のスキップを確認する。0.3.2以前は記事形式未対応なので読み戻し先は0.3.3以降。更新後のおしゃべりnoteも同じ記事形式に対応。両方向の書き出し・読み込みで記事を含む5種類を受け渡せる。相手リポジトリは変更しない。

## 登録と画面

通常モードの公開記事で、URLとdata-note-keyが一致する既知記事枠のタイトルをDOMから得る。本文の取得・保存は不要。既存の作者・マガジン・メンバーシップ用フォームを再利用し、&ボタンで登録先の4グループと追加ボタンを開閉する。TLの前に&ボタンを配置。既存の広幅・余白条件を守る。登録フォームはEscapeで閉じる。狭幅ではハンバーガー内の先頭に&＋TLの行、その直下に開閉フォームを全幅配置する。作者2列・前後2列・全文取得の構造は維持する。

登録済みの場合は登録先を示し追加を無効化。未確認タイトル、プレビュー、非記事、拡張OFF、通常以外のモードでは記事登録UIを出さない。画面遷移で旧記事の登録を実行しない。バックグラウンドは既存の送信元検査・現在タブURL・遷移中URL・保存直前の再確認を用い、表示中の記事IDとリクエストの記事ID・URLを照合する。保存失敗・結果不明は既存の再確認UIを再利用する。

専用ホームとnote上のお気に入りには&タイトルを表示し、元記事を開く。専用ホームでは同じタブ、note上は既存のマガジン等と同じ別タブ。タイトルはtextContentで表示。削除・上下移動・ドラッグ並べ替え・グループ移動を既存操作で扱う。
