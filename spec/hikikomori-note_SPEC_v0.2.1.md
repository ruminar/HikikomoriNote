## 3. グループUIと画面遷移

### 3.1 4つの固定枠

初期実装は最大4グループを「4つの常設枠」で実現する。作成・削除・グループ自体の並べ替え・増減は実装しない。空の枠も選べる。安定IDと表示番号の対応を固定する。

| ID | 表示番号 | 名前未設定時 |
|---|---|---|
| `group1` | ① | グループ1 |
| `group2` | ② | グループ2 |
| `group3` | ③ | グループ3 |
| `group4` | ④ | グループ4 |

名前は前後空白を除いた任意の文字列、最大40 Unicodeコードポイント。改行・制御文字と不正なUnicodeは拒否する。空欄保存は既定表示へ戻す。名前の重複は許可し、IDで区別する。HTMLとして解釈せずtextContentで表示する。

### 3.2 最小の左メニュー

```text
フォロー中のTL
[ タグをお気に入りに追加 ] ← 未登録のタグ画面だけ
お気に入りタグ
[ ① ][ ② ][ ③ ][ ④ ]   ← 見出しとタグ一覧の間
技術系                    ← 選択中の名前。長い場合は1行省略＋title
# ComfyUI
# AI
```

お気に入りタグの選択表示は、タグ画面のタグ名だけでなく、記事検索（context=note、または既定のcontext未指定）のqが「#保存タグ名」と完全一致する場合も対象とする。並び順には依存しない。通常キーワード・他の検索対象・部分一致は選択表示しない。検索種別自体は変更せず、検索画面にタグ追加ボタンは出さない。検索語と対象のSPA変更でも描画判定を更新する。

番号はリンクではなく `button type="button"`。押してもlocation・history・noteの検索条件・本文・スクロール位置は変更しない。変更するのは選択表示、グループ名、タグ一覧、現在タグの追加可否だけ。TLリンク先は従来どおり `/following`。

4ボタンを「お気に入りタグのグループ」というrole=group内に置き、選択をaria-pressedで示す。各ボタンのaria-labelとtitleは「① 技術系」のように名前を含める。通常のTab・Enter・Spaceで使えるようにし、専用ホームの左メニュー操作と混同しない。選択後は対応番号のフォーカスを維持し、再描画でbodyへ飛ばさない。

| 方式 | 利点 | 欠点 | 採否 |
|---|---|---|---|
| ①②③④を直接選択 | 1操作で目的地へ移れ、数・現在位置が見える | 4ボタン分の幅が必要 | 採用。既存左幅内で等幅配置 |
| ◀・▶ | ボタンが2個で済む | 目的グループまで複数操作、端の扱いと番号表示が別途必要 | 不採用。4枠では部品数・操作数の利点が小さい |

矢印との併設はしない。公式左カラムが存在しない・非表示の場合は、番号だけを別の場所へ無理に挿入しない。

### 3.3 専用ホーム

専用ホームは左メニューと右メイン領域の2カラムにする。メイン画面・上部タブは廃止する。左メニューの「お気に入りタグ」「設定」で右側だけを切り替え、noteへの画面遷移は起こさない。区切り線の下に「前の画面に戻る」「<ユーザー名>のページ」「フォロー中のTL」を置く。「前の画面に戻る」はtype=buttonであり、通常・重度・拡張OFFで表示する。専用ホーム用のgoBackUnrestrictedからhistory.backを1回呼び、オリジン判定・Navigation API・設定保存・専用ホームへの代替転送は行わない。履歴がない場合はその場にとどまる。ロゴの同一オリジン限定goBackとは分離する。ユーザー名のページは重度モード・拡張OFFでも表示する。ユーザー名未設定では「自分のページ（未設定）」とし、遷移先を付けず無効表示にする。未選択のメニューボタンにも枠線を表示する。通常の初期表示は「お気に入りタグ」、#settingsから来た場合は「設定」。狭い画面では縦積みにする。

- 重度ひきこもりモードでは左の「お気に入りタグ」とTLを隠し「設定」と自分のページへの入口を残す。右側上部のキャッチコピーは重度モード中は常時表示する。通常の初期表示はこのメッセージだけとし、「設定」を選べば設定フォームを表示できる。#settingsから来た場合は重度でも設定を直接開く。設定フォームからモードを保存した場合はフォームを開いたままにする。モード解除でタグ管理を復元し、入力・タグ・並び順は保持する。
- お気に入りタグ：番号選択＋選択名、グループ名入力と「名前を保存」、既存のタグ入力・追加・編集一覧の順。
- タグ変更は操作ごとに自動保存。名前は入力途中を共有せず、保存ボタンで確定する。番号切り替えも独立した即時保存操作とする。
- 各タグ行に移動先グループのselectと「移動」を追加する。移動は `TRANSFER_TAG`（groupId・targetGroupId・tag）として同じキューで処理し、元の削除と移動先末尾への追加を1回で保存する。保存失敗では元に残し、移動先に同じタグがある場合はCONFLICTとしてどちらも変更しない。コピー機能は追加しない。
- グループ名の変更を全体の「ユーザー設定を保存」に混ぜない。タグ・グループの一括配列保存も導入しない。
- 全ホーム・noteタブで同じ「最後に選んだグループ」を共有する。別タブでの選択は既存のstorage変更通知で反映し、「別の画面でグループが切り替わりました」と状態領域で通知する。
- タグ入力と未保存の名前は画面ローカルでグループID別に保持し、選択切り替え・外部更新でも消さない。送信中の入力と送信後の追加入力も区別する。
- ドラッグ開始時のgroupIdを保持する。途中でグループが変わったらドラッグを取り消し、別グループへの移動として扱わない。
- 同じ画面の保存待ち中は次の変更操作を無効化する。通信待ちで楽観的に選択・一覧を確定しない。

## 4. データ構造

storage.localのキーは `hikikomoriNote.settings.v2` とし、4グループの保存形式だけを扱う。`tagSchemaVersion: 2` は現行形式を識別するための値とする。

```js
{
  enabled: true,
  noteUserId: "ruminar",
  dashboardDisabled: false,
  legacyMode: false,
  hideArticleRecommendations: false,
  hidePaidArticles: false, // 有料記事カード非表示。初期値OFF
  noteLogoBrowserBack: false, // 新規。未設定はfalse

  tagSchemaVersion: 2,
  tagGroups: [
    { id: "group1", name: "", tags: ["ComfyUI", "AI"] },
    { id: "group2", name: "", tags: [] },
    { id: "group3", name: "", tags: [] },
    { id: "group4", name: "", tags: [] }
  ],
  selectedTagGroupId: "group1",
  groupSelectionRevision: 0, // 選択が変わった保存時だけ増加。A→B→Aも検出
  tagGroupsRevision: 0      // グループ関係の保存時に増加。応答の新旧判定用
}
```

- 正本はversion=2の `tagGroups` と選択情報のみ。タグの保全用別配列は持たない。
- 4つのIDをそれぞれ1回だけ含むこと、ID順、name/string、tags/array、選択ID、非負の安全整数のrevisionを検証する。revision上限到達時は書き込みを止め、周回させない。
- 同じタグはグループをまたいで登録可能。同一グループでは既存normalizeTagの保存値完全一致のみ重複拒否。Unicode正規化・大小文字・全半角の自動変換は追加しない。
- タグ件数の固定上限は追加しない。storage容量のエラーは保存失敗として扱う。
- UIは `selectedGroup(settings).tags` 相当の共通ヘルパーを使用する。診断・読み取り専用状態は派生値であり永続化しない。
- `readSettings` は純粋な解釈・検証のみを行う。画面側の読み込みで保存をしない。

## 5. 新規開始と保存データの検証

保存領域は hikikomoriNote.settings.v2 のみを使用する。0.1.x・0.2.0の設定やタグを読む処理・変換処理・保全用コピーは設けない。別の保存領域は参照・削除しない。

- 保存値が未作成（undefined）の場合だけ、名前なし・タグなしの4グループ、選択①、更新番号0の初期状態を返す。
- 初期状態では拡張ON、ユーザー名空、ダッシュボード制限・おすすめ非表示・重度モード・ロゴのブラウザバックはOFF。
- 読み込みだけではstorageへ書かない。最初の設定・グループ操作が成功したとき、現行形式を保存する。
- version=2、固定4ID、配列・名前・選択ID・更新番号を検証する。保存済みの値が不正な場合は、新規状態と区別して警告し、自動初期化しない。
- 一部のタグが不正な場合は正常項目を読み取り専用表示し、グループ編集を止める。通常設定の保存でも元のグループ領域を保持する。
- グループは正常で選択IDだけ不正な場合は①を暫定表示し、番号を明示的に選び直して選択情報だけを修復できる。
- 未知schema・不正revisionではグループ変更を停止する。元の値を0や空配列に置き換えない。
- 保存失敗時は保存済みデータを維持し、結果未確認時は手動再確認する。バックアップ管理UIは設けない。

## 6. 保存・同期・競合対策

### 6.1 操作単位の更新

既存の一つのPromiseキューを維持し、グループ選択・名前保存・タグ操作・一般設定保存を受信順に処理する。画面からtagGroupsやtags配列そのものを受け付けない。概念的な操作は以下とする（実行コードではない）。

```js
{ type: "SELECT_TAG_GROUP", groupId: "group2" }
{ type: "RENAME_TAG_GROUP", groupId: "group2", name: "創作", expectedName: "" }
{ type: "ADD_TAG", groupId: "group2", tag: "ショートショート" }
{ type: "REMOVE_TAG", groupId: "group2", tag: "ショートショート" }
{ type: "TRANSFER_TAG", groupId: "group1", targetGroupId: "group2", tag: "AI" }
{ type: "MOVE_TAG", groupId: "group2", tag: "AI", beforeTag: "ComfyUI" }
// beforeTag: null はそのグループの末尾
```

各操作は最新rawを再読込・検証し、対象グループだけを変更して保存する。ADDは末尾、重複はCONFLICT。REMOVE/MOVEの対象や移動先が消えていた場合もCONFLICTで保存しない。同じ値への名前保存・同じグループ選択・自分自身への移動は変更なし。名前はexpectedNameが最新と異なる場合に競合を通知し、他タブの改名を無言で上書きしない。

グループ選択は最後に保存が成功した要求を採用する。複数タブで別番号を選んだ場合も、全タブに同じ選択を通知する。選択変更だけでは一般設定やタグを上書きしない。

タグ・名前変更は、ユーザーが操作を始めたgroupIdへ適用する。別タブで選択が変わっても別グループに読み替えない。画面には対象番号・名前を含む保存結果を表示する。通常設定のdirty値とグループ別の未確定入力は既存方式と同様に保持する。

### 6.2 タグページからの追加と送信元の権限

`add-current-tag` は引き続きURLから背景側でタグを導出する。新たに、画面が見ていたgroupIdとgroupSelectionRevisionを送る。操作時の最新選択ID・revisionの両方が一致した場合だけ、そのグループへ追加する。

SPA遷移ではsender.urlと現在表示中のURLが異なる場合がある。contentは操作時のlocation.hrefをpageUrlとして送信し、背景は自拡張ID・トップフレーム・noteオリジン・タブIDを確認したうえでtabs.getにより現在のタブURLを取得する。pageUrlとの一致を確認し、そのURLから画面種別・タグを導出する。sender.urlの古いパスや送られたタグ名だけでは判定しない。URL不一致・別ページへの遷移中・タブ取得失敗・対象外画面はCONFLICTとして応答し、保存しない。非同期のURL確認中もメッセージ応答チャネルを維持する。既存のnoteホスト権限を用い、新しい権限は追加しない。

別タブが①→②→①と切り替えた場合もrevisionの違いで検出する。不一致ならCONFLICTを返し、最新状態を読み直して「選択グループが変わりました」と通知する。勝手な対象変更・自動再送はしない。登録済み判定は選択グループのみ。他グループにあるタグでも追加可能で、現在グループへ登録済みならボタンを隠す。

| 送信元 | 許可する操作 |
|---|---|
| 検証済み拡張home.html | get-state、一般設定の部分保存、グループ選択・改名・タグ編集 |
| 自拡張ID・トップフレーム・有効タブ・対象URLを検証したnoteのフォロー中/タグ/検索/トピック配下 | グループ選択のみ |
| 上記のタグ画面 | 加えてadd-current-tag。タグ名はブラウザで確認した現在のタブURLから導出 |
| その他・外部ページ・iframe・不明なメッセージ | 拒否 |

content側からの選択操作は、背景で実行時にenabled=trueかつlegacyMode=falseを確認する。受信groupIdは固定4IDのいずれかに制限する。一般設定・配列の書き込み・改名・削除・移動はnote画面へ開放しない。

### 6.3 同期、応答喪失、背景再起動

- 同一ブラウザ・プロファイル内でstorage.onChangedを利用する。端末・ブラウザ間のsync保存は導入しない。
- グループ関係の保存はtagGroupsRevisionを増加させ、古い応答で新しいグループ表示を巻き戻さない。既存の画面内revisionガードも維持する。一般設定の変更通知後に、過去のグループ応答の設定全体を再適用しない。
- Promiseの受付だけでは成功にしない。storage保存後にのみ成功応答する。既知の失敗では最後に確認した選択・一覧へ戻し、入力を保持する。
- UNCONFIRMEDではその画面のグループ変更を止め、再確認が成功するまで自動再送しない。sidebarにも既存の状態表示・再確認ボタンを再利用する。
- 背景が停止した時点で保存済みなら再取得でその状態を採用し、未保存なら以前の状態から再開する。メモリー内の未完了操作を復元・再実行する仕組みは作らない。
- グループ操作ではDNRを更新しない。一般設定は現行のルール適用・保存・失敗時のルール復旧を維持し、新しいグループ領域を部分保存で失わない。

## 7. noteロゴのブラウザバック設定と識別

### 7.1 設定UI

確認ダイアログ方式を廃止する。noteLogoBrowserBack:boolean、初期値・未設定はfalse。設定名は「noteアイコンをブラウザバックに差し替える」。通常の「ユーザー設定を保存」で永続化し、部分保存・型検証・保存失敗時の復旧・別タブ同期を既存方式に統合する。以前の確認フラグは使用せず、新しい設定へ変換しない。

ONなら識別済みの公式ロゴの通常クリックでブラウザバックする。Navigation APIのcanGoBackがtrueならnavigation.backで同一オリジンの直前へ戻る。戻る先のURLや履歴一覧は取得・保存しない。直前が外部や拡張ホームの場合、履歴なし、API未対応、戻る処理の同期例外・完了失敗ではフラグメントなしのhome.htmlへ移動する。設定OFFなら従来どおり専用ホームへ移動。拡張全体OFFではロゴへの介入を停止して公式動作へ戻す。重度モードでもブラウザバックは有効。

### 7.2 公式ロゴの識別

2026-10-25に確認したheader[data-header-state="navbar"]内のホームリンクとsvg[role="img"][aria-label="note"]の組み合わせを継続使用する。クリックのcomposedPath上の接続済みaがisHomeを満たし、article/#note-body/拡張追加UI内でないことを確認する。hrefだけで識別しない。DOMが一致しなければブラウザバックを追加せず既存のホーム転送動作を維持する。

### 7.3 設定画面への入口

TLの上へ追加していた「設定画面を表示」は全画面から撤去する。ロゴのブラウザバック設定ONかつ拡張ONなら、識別済みの公式ヘッダーロゴの右隣に単色SVGの歯車リンクを追加する。hrefはplatform.homeUrl()（フラグメントなし）、aria-label/titleは「設定画面を表示」。重度モード・左メニューがない画面・狭い画面でも、確認済みのロゴ親要素があれば利用できる。

ロゴの親がdivで、拡張所有要素を除く子要素がそのロゴ1個だけの場合に限り、親へ独自レイアウト属性を付け横並び・8px間隔とする。歯車は32pxの操作領域・22pxのSVGとし、ロゴのhrefやクリック動作は変更しない。未確認の親構造には挿入しない。既存のDOM更新処理でロゴの後挿入・差し替えに対応し、重複追加を防止する。設定OFF・全体OFF・停止・DOM境界の不一致で歯車と独自属性を除去する。

記事の固定位置は設定にかかわらずTL72px、作者120pxを維持する。記事の幅条件はTL/作者だけに適用し、歯車には適用しない。専用ホームには左メニューの「設定」が常にあるため追加ボタンを置かない。

## 8. ロゴのブラウザバックとクリック・SPA・DNRの関係

既存のdocumentキャプチャ処理で、有効・通常主ボタンクリック・isTrusted・cancelable・修飾キーなし・downloadなし・同一タブtargetの公式ロゴだけを対象にする。preventDefaultとstopImmediatePropagationを先に実行し、ブラウザ差分アダプターのgoBackを1度呼ぶ。アダプターはnavigation.canGoBack===trueかつback利用可能の場合だけnavigation.back()を呼び、finishedの成功後true、それ以外はfalseを返す。history.backへ代替しない。falseならplatform.homeUrl()へlocation.assignする（#settingsなし）。confirm・独自モーダル・合成クリックは使わない。連打は未完了の1回へまとめ、待機中に別URLへ移動した場合や設定/全体OFFになった場合はフォールバック転送で割り込まない。

修飾クリック・中ボタン・新規タブ・ロゴ以外のホームリンクは既存処理を維持する。URL直接入力・ブックマーク・ブラウザ本来の戻る/進むを新たにブラウザバックへ差し替えない。既存のホーム/Dashboard DNRとSPAフォールバックは維持するため、戻る先自体が制限対象URLなら既存制限が適用される。

クリック時に保存処理や非同期の履歴照会は行わない。動的なロゴ差し替えはクリック時の識別で対応し、設定リンクは既存の描画・設定同期・撤去経路に統合する。初期設定読込前や、note側の先行イベントが既に遷移を開始した場合の完全な介入は保証しない。対象外のクリックへ範囲を広げたりMAIN worldへ注入したりしない。

## 9. ON/OFF・重度モードとの関係

表示名は、標準動作を「通常モード（ひとみしりモード）」、legacyMode=trueの動作を「重度ひきこもりモード」、拡張OFFを「通常のnote」に統一する。設定チェック項目は「重度ひきこもりモード」とし、説明で0.1.1相当であることを補足する。OFF時の状態表示には保存中のモード名を併記しない。内部フラグと保存済みのモード選択は変更しない。

| 状態 | グループUI/変更 | ロゴのブラウザバック | 既存制限 |
|---|---|---|---|
| 全体ON・通常 | ホーム/共通左メニューで有効 | 設定ONなら有効 | ホーム転送、dashboard/おすすめは既存設定どおり |
| 全体ON・重度 | UIを隠し、変更要求も拒否。名前・タグ・選択は保持 | 設定ONなら有効 | dashboard/おすすめを含め0.2.0と同じ |
| 全体OFF・通常 | note上のUI・変更は停止。直接開いた専用ホームでの管理は現行どおり可能 | 停止。設定は保持 | DNR解除、追加UI除去 |
| 全体OFF・重度 | タグ/グループUIは表示せず保持 | 停止。設定は保持 | 公式表示 |

既存のOFF操作はルール解除と保存の成功後に通常ホームへ移動し、グループ・ブラウザバック設定を消さない。toolbarによるON復帰も選択を維持する。ロゴのブラウザバックを理由に通常ホーム転送を解除したり、ダッシュボードルールを変えたりしない。

## 10. Chrome・Edge・FirefoxとDOM監視

- 現行Manifest V3・既存権限storage/declarativeNetRequestWithHostAccess/noteホスト権限を維持する。tabs、webRequest、scripting等の追加権限は不要。
- ChromiumはService Worker、Firefoxは現行の背景scripts/Event Page。同じキュー・操作検証を使用する。Firefoxデスクトップ140以降という現行対象を維持し、Android対応を新たに保証しない。
- Navigation APIの対応有無を実行時に検出する。既存のFirefox最低対応バージョンは変更せず、APIのない環境は専用ホームへ移動する。Chrome・Edge・Firefoxで同一オリジン/外部直前履歴/履歴なし/失敗を実機確認する。
- contentの既存MutationObserver・storage通知・SPAフォールバックを再利用する。グループUI用に全a・全DOMの走査や短周期timerを追加しない。ロゴのブラウザバックはクリック経路上の局所検査だけ。
- グループ操作時は既存メニュー内のグループ領域を更新する。選択番号・グループ名/一覧のrevisionを描画signatureへ含め、変化がなければ再描画しない。独自UIの変更をobserverで再処理しない現行ガードを維持する。
- noteのヘッダー・ロゴ自体のDOMやhrefを書き換えない。既知の左カラムを特定できない場合は公式表示を維持する。OFF/重度/停止では独自グループUIと公式メニュー非表示属性を既存restore経路で片付ける。

## 追加仕様：有料記事の非表示

設定画面に「有料記事を非表示」を追加する。hidePaidArticlesはbooleanで初期値・未設定時ともfalse。既存の背景キューで部分保存し、storage.localと変更通知で永続化・同期する。保存失敗時は従来値を維持する。通常・重度ひきこもりの両モードで有効。全体OFF、設定解除、停止時は拡張が付けた非表示属性を外す。

note上で確認できる一覧の記事カードを対象とし、公式画面・記事取得APIは再実装しない。提供されたHTMLに基づき、grid-rows-subgridのカード枠、その直下のカード内にあるabsolute/inset-0のタイトル・aria-label付き記事リンク、h3、text-text-successの価格spanを組み合わせて判定する。価格欄全体の文字列が正の円価格（例：¥300、¥1,200）の場合だけ枠へ専用属性を付けて隠す。一覧で空き枠を残さないため、カード外のcontents、mb-0/w-full/min-w-0/border-b-0/pb-0、無クラスdivの既知ラッパーも、子要素が1個の場合に最大3段まで含めて非表示にする。一覧全体や複数カードを含む親は隠さない。復元時は実際に隠した外枠の属性を外す。記事本文内・商品リンク・価格不明・不明なDOM構造は対象外とする。カードの構造が異なる画面は表示を維持する。

https://note.com/notes/purchased（クエリ・末尾スラッシュ・配下を含む）は常に除外。SPAで移動した場合も既存カードの非表示を解除する。他の一覧では購入済みでも価格表示があれば対象となる。購入状態を取得・推定しない。記事URLへの直接アクセスは制限しない。

既存のMutationObserverを共用し、DOM更新時に価格カードの再確認を予約する。文字列の変更も監視するが、独自属性の変更は監視せず再帰を防ぐ。同じURL・設定でDOM更新がなければ定期処理から価格欄を再走査しない。後から追加されたカード、価格の消失・カードの再利用でも表示を再評価する。新規権限・依存ライブラリ・外部通信は追加しない。

## 追加仕様：ヘッダー検索欄のクリア

拡張ON時、通常・重度の両モードで公式ヘッダー検索フォームにクリアボタンを追加する。新しい設定は設けない。既存の共通ヘッダー非変更方針に対する、今回の明示的な追加要件に限った例外とする。

確認した境界はheader[data-header-state="navbar"]内のform[role="search"]（actionはnote.com/search）、直下のdata-name="Field"、data-name="TextFieldBase"の直下のinput[type="search"][name="q"]（aria-label="キーワードやクリエイターで検索"）。本文側・モバイル等の異なる未確認フォームは変更しない。

フォームの末尾にtype=buttonのクリアボタンを配置し、独自属性がある間だけ横並び・8px間隔、入力側を可変幅として検索欄の右隣に置く。ボタンは32px、単色のインラインSVGで×を描画し、aria-label/titleを「検索欄をクリア」とする。SVGは装飾扱いとし、外部画像・絵文字・依存ライブラリは使わない。

入力がある場合だけボタンと追加レイアウトを表示する。クリックでは既定動作・バブリングを止め、HTMLInputElement.prototype.valueの標準setterで空文字へ変更し、bubbles/composed付きinputイベントを送って公式の入力状態へ反映する。検索・submit・URL変更は実行しない。入力欄へフォーカスを戻す。日本語等のIME変換中は無効にする。

入力・変換イベントと既存のDOM更新/URL確認処理を共用し、SPAの入力差し替えでは古いボタン・イベント・独自属性を除去して再作成する。OFF・停止時も同様に撤去し、入力値は消さない。公式DOMが境界に合わない場合は追加しない。検索文字列の保存・ログ記録・外部送信は追加しない。権限とブラウザ依存APIは変更しない。

## 追加仕様：トピック画面の左メニュー

note.com/topic/の後に空でないパスがある画面（例：/topic/education_learning、クエリ・末尾スラッシュ・下位パスも含む）をtype=topicとして扱う。/topicと/topic/自体は対象外。既存のaside（sticky、w-[11.375rem]、急上昇nav、表示可能という境界）を共用し、通常モードかつ拡張ON時にTL帰還リンク・グループ切り替え・選択名・タグ一覧を表示する。既存の公式トピック一覧や記事の内容・遷移は変更しない。現在タグの追加ボタンは表示しない。

背景の現在タブURL検証でtopicもグループ選択操作だけ許可する。add-current-tagはタグ画面に限定したまま維持する。OFF・重度モード・対象外URLへのSPA遷移では公式左カラムを復元し、未確認・非表示のasideへは追加しない。

## 試験仕様：SSRのグリッド親から左領域を先行制御

利用者提供のJavaScript停止時HTMLで、初期ローダーはaside内ではなく、min-h-screen・lg:grid・lg:grid-cols-[202px_minmax(0,1fr)]のグリッド直下にあることを確認した。mainもこのグリッド直下にあり、asideの内容は別のhidden領域から挿入される構造となっている。

対象URLは従来のfollowing/tag/search/topic。完成したasideや急上昇navを待たず、min-h-screen・lg:gridに加え、幅指定がlg:grid-cols-[202px_minmax(0,1fr)]またはlg:grid-cols-[12.625rem_minmax(0,1fr)]のdivにhikikomori-note-navigation-rootを付与する。既存MutationObserverの開始を設定読込より前へ移し、設定待ちでも親の出現に対応する。初期準備では対象URLなら先行適用し、設定確認後は通常モードかつ拡張ONだけで維持する。OFF・重度・対象外・停止・親の切断/構造変更で独自クラスだけを除去する。設定未確認の間はOFFでも一時的に適用される。

CSSは.root > div.py-4で左ローダーを、.root > aside > div > div.flex.flex-col.gap-4で公式メニューを隠す（.rootはhikikomori-note-navigation-root）。タグ画面等のdiv.hidden.lg:contentsが間に入る構造にも、.root > div[class~="lg:contents"] > div.py-4と.root > div[class~="lg:contents"] > aside > div > div.flex.flex-col.gap-4で対応する。main内のローダーや記事、独自ナビゲーションはこの構造に一致しない。後から追加される子要素にもCSSが自動で適用される。独自メニューの作成と復元は既存の方式を維持し、未確認の別グリッドにはクラスを付けない。

公式メニューの取得通信は変更しない。独自タイマーや追加権限は導入しない。親がまだ見つからない場合や公式DOMが変わった場合のちらつき解消は保証せず、実機で初回・SPA・低速描画を確認して採否を決める試験実装とする。

## 16. 技術資料

以下は2026-10-25に確認した標準APIの根拠。noteロゴのDOMは第7.2節の実サイト観察であり、API仕様による保証ではない。

- [MDN: Event.preventDefault](https://developer.mozilla.org/en-US/docs/Web/API/Event/preventDefault)：標準動作のキャンセルとcancelable/passiveの制約。
- [MDN: Event.stopImmediatePropagation](https://developer.mozilla.org/en-US/docs/Web/API/Event/stopImmediatePropagation)：後続リスナーの停止と、すでに実行した先行リスナーは取り消せないという設計上の限界。

- [HTML Standard: Navigation API](https://html.spec.whatwg.org/dev/nav-history-apis.html)：直前が異なるオリジンならcanGoBackはfalseとなり、backの履歴移動も同一オリジンに限定される。

/hashtag/タグ名と/tag/タグ名は元から同じtag種別として共通処理する。未ログインの実DOMで/hashtag/ComfyUIから/tag/ComfyUIへの転送、rem表記の親とlg:contentsラッパーを確認。/hashtag自体は通常ホームへ転送されたため、新しいタグ一覧種別は追加しない。

検索画面の実DOMではグリッド直下がdiv.hidden.lg:blockで、その中に共通asideがある。lg:contentsに加え、このラッパー内の左ローダーと公式メニューにもCSSを適用する。main内の検索フォームは対象外。
