# ひきこもりnote 仕様書

- **プロジェクト名**: ひきこもりnote
- **リポジトリ名（案）**: `hikikomori-note`
- **版**: 0.1.0-draft
- **作成日**: 2026-10-20
- **形態**: ブラウザ拡張 / OSS
- **初期対象**: Google Chrome、Microsoft Edge
- **将来対象**: Mozilla Firefox
- **現状**: 企画・仕様策定。実装およびnote実サイトのブラウザ上での挙動検証は未着手。

## 1. 企画概要

### 1.1 キャッチコピー

> **枠を超えたら落選したので、殻を作りました。**

「枠にとらわれない創作」の結果、創作者が自分専用の枠の中に引きこもる。

### 1.2 目的

`https://note.com/` のホーム画面を、自分の記事と自分が明示的に選んだ情報だけを扱う画面へ変更する。

ホーム画面のおすすめやランキングに左右されず、noteを主に記事公開・管理の場所として使う。閲覧する外部記事は選択済みのタグから取得し、キャッシュを使って閲覧頻度・通信頻度を抑える。

これはユーザー本人の**ブラウザにおける表示のカスタマイズ**であり、noteのサーバー、他者のページ、投稿内容を変更するものではない。

### 1.3 設計原則

1. **最小構成**: 動くものを先に完成させ、機能を段階的に追加する。
2. **ユーザー主導**: 何を見るか、いつ更新するか、スキを押すかはユーザーが決める。
3. **低頻度アクセス**: 外部フィードの通常更新は原則1時間に1回。キャッシュを優先する。
4. **見える出所**: 原記事のタイトル、作者、URL、公開日時をできる範囲で表示し、要約は要約と明記する。
5. **既存操作は壊さない**: noteの投稿・編集・ログイン・購入・設定ページには介入しない。
6. **移植性**: ブラウザ依存APIをアダプターで隔離し、Chrome/Edge版とFirefox版で共通ロジックを再利用する。

## 2. 対応環境

| 対象 | 初期計画 | 特記事項 |
|---|---|---|
| Chrome | v0.1から対応 | Manifest V3 |
| Edge | v0.1から対応 | Chrome向けビルドをそのまま検証。ストア公開時は別途申請の可能性 |
| Firefox | v0.3以降 | WebExtensions対応。Manifest・バックグラウンド・サイドバー機能は差分対応 |

- Chrome/Edgeのバックグラウンドは **MV3 Service Worker**。
- FirefoxのMV3では `background.scripts` などを使用する必要がある。Firefoxは現時点で `background.service_worker` をChrome同様にはサポートしていない。
- Chrome `sidePanel` とFirefox `sidebarAction` は互換ではない。したがって**サイドバーは必須にせず、ホーム画面と設定画面を中心に設計する**。
- `note.com` のホームページだけを置換する。ブラウザの新規タブページ全体を置換する設計ではない。

## 3. 画面構成

### 3.1 ホーム画面（`https://note.com/`）

- 上段に「ひきこもりnote」の名称とON/OFFスイッチ。
- 主タブ: **自分の記事** / **選んだタグ**。
- **自分の記事**：登録した本人の公開記事一覧。note公式の投稿管理・下書き管理への導線を併設。
- **選んだタグ**：最大10タグの新着記事を統合して一覧表示。タグ単位の絞り込みも提供。
- 最終取得時刻、キャッシュ状態、取得エラー表示。
- ユーザー操作による「更新を確認」ボタンを提供。ただし通常の1時間制限を越える更新は明示確認を要求する。
- 「通常のnoteを表示」ボタンで即時に元のホームを復帰できる。

### 3.2 記事カード

必須項目：タイトル、作者名、元記事URL、タグ（取得可能な範囲）、更新・公開日時（取得可能な範囲）。

任意項目：サムネイル、説明文、AI要約、スキへの導線。

- 「記事を開く」は常に元記事に遷移。
- 「スキ」は**ユーザーの明示操作**のみ。仕様未確認のnote内部APIへの自動送信は行わない。
- 初期版は「記事を開いてスキ」の導線を用意し、note公式UIからスキを押す。将来の直接操作は認証・サイト仕様・規約を確認したうえで別途検討。
- 閲覧やスキの自動操作、まとめ押し機能は提供しない。

### 3.3 設定画面

- noteユーザー名（例：`ruminar`）。プロフィールURLから識別子を抽出してもよい。
- 表示タグ（0～10件、重複禁止、順序入れ替え、削除）。
- タグの統合表示順：新着順（初期値）、古い順、ランダム（キャッシュ内のみ）。
- 自動更新の有効/無効。更新間隔は**最短60分**。
- 取得上限、通信量節約設定、AI要約の有効/無効。
- キャッシュ削除、設定エクスポート/インポート（将来候補）。

## 4. 機能要件

### F-01 ホーム画面の置換【MVP】

- `location.origin === 'https://note.com' && location.pathname === '/'` の時のみ拡張画面を表示する。
- 既存DOMの不要部分は**表示上のみ隠す**。必要なら Shadow DOM で独立したUIを描画。
- 拡張停止時、エラー時はnote本来の画面に復帰できる。
- SPA遷移により別ページへ移動した場合は干渉を解除する。
- 編集画面、記事本文、ログイン画面、購入・決済画面などは対象外。

### F-02 自分の記事一覧【MVP】

- 設定したユーザーの公開プロフィール・公開記事へのリンクを起点に一覧化する。
- 公開記事の取得が失敗した場合、プロフィールへの直接リンクにフォールバック。
- ログイン限定コンテンツや下書きを非公式な手段で取得しない。

### F-03 タグ登録【MVP】

- タグを最大10件保持。空欄・重複・11件目を拒否する。
- 保存後ただちに表示を更新。ただし実データはキャッシュ優先。
- `https://note.com/tag/<encodedTag>` を実際の遷移先として使用（`/hashtag/` は `/tag/` へリダイレクトされる場合がある）。

### F-04 タグ記事の取得【v0.2】

- 各タグの**新着**ページを対象とし、「人気」と混同しない。
- DOMから記事カードを抽出する。noteのページ構造を確認してセレクターを決定する。
- ページ上の「もっと見る」を必要に応じて自動クリックし、読み込まれたカードを収集する。
- 検知方法は固定文字列だけに依存せず、ボタン属性・表示領域・DOM変化を組み合わせる。
- DOM追加は `MutationObserver` 等で待つ。固定時間sleepだけで成功判定しない。
- クリック処理は1タグずつ逐次実行、追加待ち・タイムアウト・中断を実装する。
- **無制限取得はしない**。初期上限の例：1回の更新で各タグ最大100記事、追加クリック最大5回。上限は検証結果に基づき調整可能とする。
- 「もっと見る」がなくなった場合、記事が増えない場合、エラー・ログイン誘導・アクセス制限が出た場合は停止する。
- 取得元URLの正規化を行い、同じ記事は複数タグで取得されても1件に統合する。
- HTMLの内部構造変更を検知したら、無理に処理を続行せず**取得不能**と表示する。
- 認証回避・アクセス制限回避・非公開APIへの依存は行わない。

※ ブラウザ上でバックグラウンドのタグページを開いて操作する方式は候補の一つ。非アクティブタブでの読み込み、画面遷移、noteの負荷、プラットフォーム規約を実地確認して方式を最終決定する。

### F-05 1時間キャッシュ【v0.2】

- `lastFetchedAt` をタグ別に記録。
- 最終成功取得から60分未満ならネットワーク要求せずキャッシュ表示。
- 60分経過後、ブラウザが動作中で自動更新ONなら次の更新機会に取得。
- 取得エラーやオフライン時も古いキャッシュを表示し、更新日時を示す。
- 同じタグへの同時更新や、複数タブからの重複要求を抑制する。
- バックグラウンド定期処理には `alarms` を使う。MV3 Service Workerの常駐を仮定しない。
- 記事カードや本文の長期保存は必要最小限とし、上限超過時は古いデータを整理する。

### F-06 AI要約【v0.3 / オプション】

- 記事本文を**取得できたときに限り**要約する。本文取得不能時は「要約できません」と明示する。
- AI未設定時は記事の公式説明文・抽出可能な抜粋を表示し、**AI要約と偽らない**。
- 1記事あたり数行の事実ベースの概要。勝手な称賛や断定的評価を要約に混ぜない。
- 要約結果は記事URLと内容フィンガープリントにひも付けてキャッシュする。
- AIが推測した内容と本文で確認できた内容を混同しない。
- 対応案：ユーザーが選択したローカルLLM（例：ローカルAPI）または任意設定のクラウドAPI。既定は無効。
- APIキーを拡張に同梱しない。外部送信する文章と宛先、料金の可能性をユーザーに明示する。
- 有料記事の購入制限や非公開記事のアクセス制限を回避しない。

### F-07 自分の記事をChatGPTちゃんに褒めてもらう【v0.3 / オプション】

- 「褒めて」ボタンを自分の記事にだけ表示。
- 実際に取得できた本文を材料に、どの記述・実装・発想がよかったか**根拠付きで**コメントする。
- 本文が読めない場合は読んだふりをしない。
- 初期案：本文・URLをコピーし、ChatGPTを別タブで開いて貼り付ける補助機能。
- 将来案：利用者が設定したAIプロバイダー／ローカルLLMで拡張内チャットを表示。
- ChatGPT公式Webアプリをiframeで埋め込むことは前提としない。
- 無条件の称賛を依頼するモードと、長所を根拠付きで挙げるモードは明確に区別する。

### F-08 通常noteモードへ戻す【MVP】

- ヘッダーから1クリックで通常のnote画面に切り替え可能。
- 拡張の有効/無効をローカル保存。次回アクセス時にも反映。
- 障害が発生しても通常noteへのアクセスを妨げない。

## 5. 非機能要件

### 5.1 パフォーマンス

- ホーム表示はキャッシュから即時に開始し、通信完了を待たない。
- 追加記事の取得は非同期。UIをブロックしない。
- 大量の記事でも仮想リストやページング等で描画負荷を抑える。
- ページ読み込みと「もっと見る」の繰り返し回数に上限、待ち時間、停止条件を設ける。

### 5.2 セキュリティ・プライバシー

- `https://note.com/*` 以外のホスト権限を安易に付けない。AI連携時の権限は別途明示。
- noteのCookie、パスワード、認証トークンを収集・外部送信しない。
- 記事タイトルや本文をHTMLとして無検証に埋め込まない。テキストとして描画しXSSを防ぐ。
- AIへ送るのは本人が許可した公開記事の必要な本文だけ。送信前に確認可能とする。
- 公開OSSにAPIキーや秘密情報を含めない。
- noteの名称と外観を使って公式サービスであると誤認させない。非公式拡張と明記する。

### 5.3 利用規約・取得ポリシー

- 利用前・公開前にnoteの最新規約と実装動作を再点検する。
- 自動化によるサーバー負荷を抑える。アクセス禁止、レート制限、ログイン要求、CAPTCHA等が出たときは処理停止。
- 第三者記事の全文データを再配布・公開しない。ユーザーのローカル表示に必要な範囲にとどめる。
- いいね／フォロー／コメントはユーザーの明示操作のみとし、自動実行しない。

## 6. データモデル（案）

```ts
type Settings = {
  enabled: boolean;
  noteUserId: string;
  tags: string[];              // 0..10
  refreshIntervalMinutes: 60; // 初期リリースは固定
  autoRefresh: boolean;
  sortOrder: 'new' | 'old' | 'random';
  aiProvider: 'off' | 'copy-to-chatgpt' | 'local' | 'cloud';
};

type Article = {
  url: string;                 // 重複判定用の正規URL
  title: string;
  authorName?: string;
  publishedAt?: string;
  thumbnailUrl?: string;
  tags: string[];
  excerpt?: string;
  aiSummary?: string;
  source: 'self' | 'tag';
};

type FeedCache = {
  tag: string;
  lastFetchedAt: number;
  articles: Article[];
  status: 'ok' | 'stale' | 'error';
  error?: string;
};
```

- 設定は `storage.local` を基本とする。
- 記事キャッシュは規模に応じて `storage.local` または IndexedDB に格納する。
- キャッシュはローカルの表示補助。同期や外部サーバーへの送信は初期要件に含めない。

## 8. 実装フェーズと完了条件

| フェーズ | 対象 | 完了条件 |
|---|---|---|
| **v0.1** | ホーム差し替え・ユーザー設定・自分の記事・通常表示切替 | Chrome/Edgeの両方でnoteトップが差し替わり、投稿・編集・ログインは影響を受けない |
| **v0.2** | 最大10タグ・新着取得・もっと見る・キャッシュ・重複排除 | タグ複数登録、最大60分のキャッシュ再利用、取得停止条件、通信障害時の復旧を確認 |
| **v0.3** | AI要約・ChatGPTへの称賛依頼・スキ導線 | 取得済み本文だけを要約し、出典に戻れ、スキが自動送信されない |
| **v0.4** | Firefoxへの移植 | 同等の機能をFirefox上で動作検証し、差分はアダプターに閉じる |

### v0.1 受け入れテスト

1. 拡張ONで `https://note.com/` を開くと専用ホームが表示される。
2. 拡張OFFで再読み込みすると通常のnote画面が表示される。
3. `https://note.com/<user>/n/<article>` 等の記事URLでは通常のページが表示される。
4. 自分のユーザー名を指定すると、公開記事に到達できる。取得不能時はプロフィールへ移動できる。
5. 設定値がブラウザ再起動後も保持される。
6. Chrome、Edgeの双方で動作する。

### v0.2 受け入れテスト

1. 10タグまで追加可能。11タグ目は受け付けない。
2. 登録タグの新着記事が統合表示され、同一URLは1枚のカードにまとまる。
3. 「もっと見る」の追加結果が取り込まれ、上限・終了条件で正常停止する。
4. 同じフィードを60分以内に再表示しても更新用通信を行わない。
5. ネットワーク不通・DOM変更・取得失敗時にもホーム画面が表示され、古いキャッシュは利用できる。
6. ユーザーの明示操作なしに「スキ」を送信しない。

## 9. 未確定事項（実装前に実機確認）

1. noteにログインしたChrome/Edgeで `https://note.com/` にアクセスしたときのDOM・SPA遷移構造。
2. タグの「新着」切替URL、記事カードの識別子、公開日時の取得方法。
3. 「もっと見る」の実DOM、非アクティブタブでの挙動、連打防止、ページ終端。
4. note側の利用条件と、ブラウザによる自動取得の許容範囲。
5. 公開プロフィールの記事一覧の構造。限定公開・有料記事・下書きの扱い。
6. 直接スキ操作を採用するか否か。初期版はnote公式ページへのリンクで代替。
7. AI要約のモデル・費用・ローカル実行方法。初期版には必須としない。
8. リポジトリ名、ライセンス、公開方法、Chrome/Edge/Firefox各ストアへの掲載時期。
