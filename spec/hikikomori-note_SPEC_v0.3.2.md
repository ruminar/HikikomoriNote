# ひきこもりnote v0.3.2 記事左メニュー

2026-11-07。0.3.1を基準に、おしゃべりnoteの「◀ 前の記事」「次の記事 ▶」「記事全文を取得」だけを移植する。要約・Ollama・記事保存・拡張間通信は追加しない。コミット・タグ・公開・リリース操作は行わない。

## 配置と対象

公開記事の既存左側メニュー（TL・作者ページ・作者の新着検索）の下に、前の記事、次の記事、記事全文を取得の順で追加する。通常・社会復帰は上232px、重度は上184px。幅200px、操作間8px。既存の公式固定作者欄は新操作領域の下へ移し、長いステータスは独立してスクロール可能にする。

既存条件（拡張ON、幅1100px以上、可視の記事枠の左端228px以上）を共用する。プレビュー・非記事・OFF・停止では新操作を撤去する。狭幅・余白不足では下記の記事ハンバーガーメニューへ切り替える。既存プレビューのTL／作者導線は維持。表示先記事とdata-note-keyが一致しなければ前後リンクを無効にし、コピーも拒否する。

## 前後の記事

確認済みの公式記事末尾カード（前の記事／次の記事ラベル、タイトル一致、_selfの公開note記事リンク）を優先。本文中・拡張UI・別記事枠・未知構造・非表示・複数候補・外部URLは採用しない。リンクは通常の同じタブ遷移で、修飾キー等は標準動作を維持する。クリック直前にも現在の記事・リンクを照合する。

スクロール前でも使えるよう、確認済み本文のある公開記事でnoteのGET `/api/v3/notes/{記事ID}/extra_items` を一度呼び、prev_note / next_noteの公開タイトルとURLだけを一時参照する。既存のnote.comホスト権限内で、credentials:omit・redirect:error・10秒タイムアウトを使う。本文・認証情報・コメント等は保存も使用もしない。有効なmagazine_keyだけを問い合わせと遷移先へ引き継ぎ、その他のパラメータやフラグメントは持ち出さない。

再描画・250ms同期で自動再送しない。失敗時は理由をツールチップに示し、ページ再読み込みを案内する。SPA移動・OFF・停止後の遅い応答を別記事へ適用しない。該当記事なしはリンク先を付けず無効表示する。公式DOMで有効なリンクが後から得られればそちらを使う。

## 記事全文を取得

利用者のクリック時だけ、表示中のDOMから次のテキストを組み立て、クリップボードへ書き込む。

タイトル：...
著者名：...
投稿日：YYYY-MM-DD（確認できなければ不明）
URL：公開記事の正規URL

本文：
...

おしゃべりnoteの共通抽出処理から、DOM抽出とURL検証に必要な関数だけを切り出す。本文#note-body[data-name=body]が一つで記事URLのIDとdata-note-keyが一致し、対応するタイトル・公開作者が確認できることを要求する。タイトル500文字・著者200文字・本文200,000文字を上限とし、空・上限超過・未知構造は切り詰めずコピーしない。

不可視要素・script・フォーム・操作部品・本文外の有料境界／コメント／おすすめ／拡張UIを除外する。画像だけのリンクは除外。通常リンク・添付・リンクカードは本文順に、表示文字と安全なHTTP(S) URLを含める。既知サービスの埋め込みURL補完も移植元と同じ規則を維持する。外部リンク先本文は取得しない。読み込み済みで元URLと一致する同一オリジンnoteカードだけ、既存のタイトル・著者を参照できる。未読込iframeを強制読込せず、スクロール・属性書き換え・追加通信で本文を増やさない。

「全文」は現在閲覧できる本文の意味。有料・会員限定の未表示部分や非表示情報は取得しない。コピーのためのネットワーク送信・永続保存・LLM送信・クリップボード読取はしない。利用者操作の同じ処理内でnavigator.clipboard.writeTextを呼び、追加のクリップボード権限は要求しない。失敗時に状態を表示し、再試行可能にする。別記事へ移った後の完了状態を新しい記事へ出さない。

## 境界と検証

新設定・保存データ・JSON形式は追加しない。DOM判定・表示管理・有料フィルタ・スキ操作は既存動作を維持する。前後情報の取得と利用者指定コピーをプライバシー説明へ反映する。

確認対象：3操作の順序、前後API・DOM優先・片側なし・雑誌文脈・遅延・失敗・SPA・無効URL、3モード・OFF・狭幅・停止、可視本文とコピー内容・日付・リンク／カード／添付・上限・失敗後再試行、タイトル／記事ID不一致、保存・LLM送信がないこと。実ブラウザとAndroidの未検証項目は報告する。

## 記事ハンバーガーメニュー（2026-11-09追加）

公開記事で画面幅1100px未満、または記事の左余白228px未満の場合、確認済み公式ヘッダのnoteロゴ左に既存と同じ「☰」を追加する。広幅・十分な余白では既存の固定左メニューを使用する。

メニューは初期状態で閉じ、TL（通常・社会復帰のみ）→作者ページ→作者の新着検索→前の記事→次の記事→記事全文を取得の順。作者を確認できない場合は作者導線を補わず、利用可能な操作だけを表示する。お気に入りや新しい検索フォームは追加しない。プレビューでは既存のTL・作者導線のみを使い、前後・全文取得は追加しない。

同じ操作要素を移動して使用する。メニュー開閉・画面幅変更で前後APIの再取得をせず、コピーの処理中・結果表示も維持する。本文はクリック時の可視DOMだけをコピーする。開閉状態はaria-expandedへ反映し、Escapeで閉じてボタンへフォーカスを戻す。リンクを選んだら閉じ、コピー時は結果確認のため開いたままにする。別記事への遷移では閉じる。非記事への移動では既存の共通メニューの判定へ戻す。OFF・停止・ヘッダ消失では撤去する。

パネル内は固定配置を解除し、幅100%、操作間8px、タップ領域44px以上、最大高さ65vhでスクロール可能にする。パネル表示時は公式固定作者欄の位置調整を解除する。新設定・保存形式・権限は追加しない。
